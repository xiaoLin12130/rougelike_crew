# 稀有度五档体系方案（只读调研，未改代码）

> 任务：道具/法杖稀有度从三档（common/rare/legendary）扩展为五档（白/绿/蓝/金/红），先调研同类游戏品质体系，再输出迁移方案。本文档只出方案，未改动任何游戏代码与数据。

## 0. 结论摘要

- 五档命名与颜色（建议）：common 白 / uncommon 绿 / rare 蓝 / epic 金 / legendary 红
- 迁移映射（推荐方案A）：旧 common 一拆二 → 白+绿；旧 rare 一拆二 → 蓝+金；旧 legendary 全部 → 红
- 现状红利：UiTheme.RARITY 已有五个 key（common/uncommon/rare/epic/legendary，2026-08-12 土豆兄弟 UI 适配时预留），颜色为 灰白/绿/蓝/紫/橙；本次只需把 epic 紫→金、legendary 橙→红、common 灰白→白
- 数据规模：items.json 293（112/124/57）、wands.json 55（13/21/21）；迁移后预计 白56/绿56/蓝62/金62/红57（道具）、白7/绿6/蓝11/金10/红21（法杖）

## 4. 三档→五档迁移映射

### 4.1 总规则（方案A，推荐）

- 旧 common → 白/绿 二拆（强度下半→白，上半→绿）
- 旧 rare → 蓝/金 二拆（强度下半→蓝，上半→金）
- 旧 legendary → 红 全保留（顶级语义不缩水，改动最小，保序）
- 方案B（备选，不推荐）：红=旧传说中 shots≥3 连发/齐射 11 把 + 顶配 5 把（约16把），其余传说降金。红更稀有，但与 2026-08-12 法杖稀有度重分类（连发类强制 legendary）意图冲突，且把已定级的传说降档易引起玩家困惑。

### 4.2 items.json（293 条）

- 分布：112 common → 白∼56/绿∼56；124 rare → 蓝∼62/金∼62；57 legendary → 红 57
- 分档标准（档内按强度中位数拆）：
  - 通用数值类（attack_speed/crit/defense/area/speed/atk 等，多为 linear）默认 白/绿
  - mechanic:xxx 流派机制条目 默认 ≥蓝
  - exp_proc 高概率（base≥0.15）或 multiplicative（倍率收益≥10%）或 tradeoff → 金/红
  - 描述含“每层+多机制/联动/质变” 升档
- 实施要求：仿照 法杖稀有度重分类.md 输出全量逐条评审表（293 行），人工复核后一次性脚本写回

### 4.3 wands.json（55 把）

- 分布：13 common → 白∼7/绿∼6；21 rare → 蓝∼11/金∼10；21 legendary → 红 21
- 硬规则（沿用重分类）：shape=rapid 或 shots≥3 → 红；每流派 ≥1 把红（现状已满足：fire2/ice1/lightning4/poison2/summon1/water2/wind2/defense1/curse2/crit3/melee1）
- 示例分档：金=poison/frost/chain/tide/light/decay_staff（elb≥0.4）+ death_rattle/pact/ice_orbit/orbit_staff（cd≤0.85，共10把）；蓝=其余 11 把
- 价格带：白120-250/绿260-360/蓝370-550/金560-690/红700-1200（严格不重叠）；带内价保留，带外价按旧带内相对位置线性映射（预计 10 把金需提价至≥560、2 把蓝（death_rattle/bedrock，现300）需提至≥370、6 把绿需≥260）

### 4.4 spells.json（cores 15 / shells 10，无 rarity）

- 现状：图鉴用分类兜底（cores/shells=rare 蓝）；game_state.gd _make_spell_choice 硬编码 spell_part rarity=“rare”
- 建议（P1）：cores 按 base_damage/cooldown 分 白∼蓝（建议不设红），shells 可选；spell_part 稀有度随 core 派生

## 5. 掉率/权重区间

### 5.1 升级三选一（drops.json item_rarity_weights）

- 旧：{common 0.70, rare 0.24, legendary 0.06}
- 新（建议）：{common 0.42, uncommon 0.26, rare 0.19, epic 0.10, legendary 0.03}（sum=1.00，满足 test_curves.py 断言）
- 说明：权重为道具级 base weight；按新池（56/56/62/62/57）估算实际出现占比 ≈ 白41%/绿25%/蓝20%/金11%/红3%（未计流派权重加成，实施时以 tools/tests/experience_audit.py 复算）
- 依据：现传说 6%→红 3% 更稀有；介于 RoR2 箱子红∼1% 与 D3 传说 2%–8% 之间

### 5.2 法杖商店（wand_shop.gd RARITY_WEIGHT / LUCKY_RARITY_BOOST）

- 旧：{100, 30, 10}；boost {1, 2, 4}
- 新（建议）：{common 100, uncommon 70, rare 30, epic 20, legendary 6}；boost {1, 1.5, 2, 2.5, 4}
- 模拟（不放回×3，池 7/6/11/10/21，10 万次）：
  lucky=0：白38.5% / 绿23.5% / 蓝19.0% / 金11.6% / 红7.3%
  lucky=10：白30.8% / 绿22.0% / 蓝20.7% / 金14.2% / 红12.3%
  两档均保持 白>绿>蓝>金>红 严格递减，且红 +5.0pp（与现有 test_wands.py “+5pp”断言对齐）
- 说明：红池 21 把偏大是红占比仍 ~7-12% 的主因；若正式版觉得红太多，走方案B 或把红权重降至 4-5

### 5.3 Boss 掉落（drops.json boss_drops）

- 现状 {legendary:1, rare:2}：经代码排查（health_pack.gd 仅读 heal_pct），两计数疑似未使用
- 建议：核对后改 {epic:1, rare:1, uncommon:1} 或删除，不影响运行

## 7. 风险与验证

- 存档兼容：rarity 不进存档（run.items 只存 id），spell_part id 不变 → 老存档零迁移
- 测试闭环：test_wands.py 抽取模拟须在新池实际分档结果上重跑（池变则权重需微调）；test_curves.py 权重和=1 保持
- 数值不强制改动：五档数值区间为“目标档位”，迁移以重标为主，仅越界条目微调（预计 <10 条）
- 颜色冲突：金档与 GOLD（金币/价格/材料）同色系 → 建议 epic 用 #ffc84d 错开；红档与 RED（危险/负值）区分 → 建议 #ff5c5c
- 红池体感：红 21 把（38%池）→ lucky0 出现率 7.3%，若仍觉多 → 方案B
