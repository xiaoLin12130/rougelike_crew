# 商店修复2报告（2026-08-13）

范围：`scripts/ui/game/wand_shop.gd`（唯一业务改动文件）＋3 个测试文件＋本文档。未改动 `data/*.json`、`game_state.gd`（仅只读调用其权重查询）与其他 UI/战斗文件。

## 一、3 项修复说明

### 1. 购买构筑后不立即关闭商店

排查结论：`_buy_build_item()` 末尾确实调用了延迟关闭（`create_timer(0.5).timeout.connect(_finish_build_close)`），`_finish_build_close` 的 `_shop_open` 守卫也正常。真正的根因是 `create_timer(0.5)` 未设 `process_always=true`：商店打开时 `game_root.gd` 会 `get_tree().paused = true`（Boss 战后开店流程），暂停期普通 SceneTreeTimer 不触发，0.5s 定时永远不会到期，商店不关闭。

此前的单测之所以通过，是因为测试脚本从不暂停游戏树，恰好漏检该场景（详见第二节测试说明）。

修复：`get_tree().create_timer(0.5, true)`（`process_always=true`，暂停期照常计时），0.5s 展示购买成功后自动 `_close_shop()`，与购买法杖行为一致；`_finish_build_close` 保留 `_shop_open` 防重入守卫（节点释放后信号自动失效、已被其他路径关闭则跳过）。

附带修复同类隐患：`_upgrade_wand` 强化成功 1.0s 关闭定时同样改为 `create_timer(1.0, true)`（同根因，暂停期永不触发）。

### 2. 购买法杖按稀有度概率区分（越稀有越难出）

排查结论：法杖上架随机逻辑在 `wand_shop.gd` 的 `_roll_offers()` → `weighted_pick()`（静态），稀有度权重为 `RARITY_WEIGHT` 常量，不读 `drops.json` 的 `item_rarity_weights`（后者只用于升级三选一）。`wands.json` 未动，`rarity` 三档 common/rare/legendary。

实际分布（旧权重 70/25/13 × 池 13 common / 21 rare / 21 legendary，实测 1000×3 次）：

| 稀有度 | 池数量 | 旧实出占比 |
| --- | --- | --- |
| common | 13 | 53.3% |
| rare | 21 | 30.7% |
| legendary | 21 | 16.0% |

金色法杖出现偏多（3 抽至少 1 金概率约 40%）。

修复：`RARITY_WEIGHT` 改为 common 100 / rare 30 / legendary 10，实出约 60% / 29% / 10%，进一步拉开差距。

lucky 联动保留（`weight = base × (1 + lucky × 0.06 × boost)`，boost legendary 4.0）：lucky=10 时实出 47% / 35% / 18%，仍保持 common > rare > legendary，幸运流派拿金杖的成长感不变。

### 3. 商店刷新金币按次数递增

排查结论：`_refresh_count` 确实每次刷新递增（`_refresh_offers()` 与 `_reroll_build_offers()` 扣款后均 `_refresh_count += 1`，`_refresh()` 不重置，仅 `show_shop()` 开店时归零）。价格递增逻辑 `REFRESH_PRICE * (1 << _refresh_count)` 本身有效：80 → 160 → 320 → 480（封顶）。

用户"没生效/不明显"的根因：刷新按钮文字只在 `_build_buy_page()` 构建时写了一次，`_refresh()` 从不更新，按钮永远显示 80 金，玩家看不到涨价。

修复：新增 `_refresh_btn` 成员引用并在 `_build_buy_page()` 赋值；`_refresh()` 每次把 `刷新（%d金）` 同步为当前 `_refresh_price()`，按钮文字实时反映价格。

## 二、测试说明（含测试自身修复）

调试中发现 `test_wand_shop_ui.gd` 存在结构性假通过：`_run()` 以"发射后不管"方式调用含 `await` 的检查函数（`_check_lock_buttons` / `_check_build_buy_closes` 等），协程在首个 `await` 处挂起后控制权立即返回调用方，随后 `_finish()` 检查失败列表并 `quit()`，挂起协程从未恢复执行，历史报告中的"锁钮/构筑关闭断言全过"实际未运行过任何断言。

修复：`_run()` 逐个 `await` 各检查协程；`_check_build_buy_closes` 的 `shop_closed` 监听由 lambda 改为成员变量（GDScript lambda 按值捕获，回调写局部变量不生效，与 game_root.gd 记录过的坑一致）。

`test_wand_shop_ui.gd` 新增/更新：

1. 构筑购买后暂停游戏树等待 0.9s（真实复现 Boss 战后开店场景），断言 `shop_closed` 发出且商店自动关闭（修复前此用例因不暂停而漏检）。
2. 刷新费递增 80→160→320→480→480 逐次断言，含 `_refresh_count`、扣款与按钮文字实时同步。
3. 稀有度分布：1000 次 `_roll_offers()`（每次 3 把），断言 legendary < 15% 且显著低于 common、common > rare > legendary。
4. 移除 LockBtn 断言（v51 已去锁图标，改为断言不存在）；购买页网格改为 columns=1（v50 每根法杖一行）；购买验证改为直接点购买按钮。

`test_wand_shop_flow.gd`：`_check_buy` 同步更新为 v50/v51 设计（columns=1、卡片纵向不重叠、LockBtn 数量 0），消除与已提交设计冲突的陈旧断言。

`test_wand_shop.gd`：新增 lucky=0 下 legendary < 15%、common > 50% 的收紧断言。
