## 0. 审计口径

| 档位 | 含义 |
|---|---|
| ✅ 落地 | 机制道具在 items.json 落库，且脚本逻辑可被触发（门控 id 存在 / 总层数解锁），效果自结算或主线程已消费 |
| ◐ 部分落地 | 逻辑与道具就绪，但依赖主线程读取点未接线 / 条件性生效（如无击退源）/ 近似实现 |
| ✗ 未落地 | 无道具或无逻辑，或门控 id 不存在于 items.json（死代码） |

### 2.10 暴击暴伤流 — 机制 4/10（核心缺口）

`const M1..M10 := "crit_overflow_damage" / "crit_deadly_combo" / "crit_crit_bounce" / "crit_weak_mark" / "crit_storm_spread" / "crit_execute" / "crit_crit_echo" / "crit_headhunter" / "crit_lethal_blow" / "crit_crit_storm"` —— 这 10 个 id 在 items.json 中 **0 命中**；
`const CM1..CM9 := "crit_m1".."crit_m9"` —— 与落库道具一致，N2 处理器 `_on_n2_m*` 可正常触发。

| # | 文档机制 | 状态 | 现状（实际生效的是什么） |
|---|---|---|---|
| 暴M1 | 溢出转伤 | ✅ | 双路径：`_sync_stats` 被动 1:1 转暴伤（持有任意 crit 道具即生效）+ crit_m1 溢出→真伤（上限 ×2） |
| 暴M2 | 致命连击 | ✅ | crit_m3 暴击连击（+15%/层，retuned）；脚本 `_on_m2` 死代码 |

| 暴M5 | 暴风扩散 | ✅ | crit_m5 暴击爆炸（30% + 10%/层，周围 50% 暴击伤害） |

另落库了 4 个文档外新机制：crit_m2 暴击吸血、crit_m4 暴击减速、crit_m6 暴击穿透、crit_m8 完美暴击（N2 替换品）。

**补全建议（P0，改动最小）**：机制逻辑全部已写好（`_on_m3/_on_m4/_on_m6/_on_m8/_on_m9/_on_m10`），
只需在 items.json 补 6 个道具（id 与脚本常量一致：crit_crit_bounce / crit_weak_mark / crit_execute /
crit_headhunter / crit_lethal_blow / crit_crit_storm，稀有度传说 4 + 稀有 2，机制 tags `mechanic:crit_*`），
或把脚本常量改指到新道具 id；随后 6 个机制即被激活。
数值：10/10（crit_staff 走 attack_speed aggregate；crit_lucky 由 projectile 幸运重掷消费 ✓；其余由 `_sync_stats` 接管 ✓）。
