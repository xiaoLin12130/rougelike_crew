# 法术核心 × 法术外壳 组合逻辑审计（15×10 = 150 组合全检）

- 审计日期：2026-08-10
- 审计方式：只读代码审计（未运行游戏）；依据 `data/spells.json`、`scripts/combat/spell_caster.gd`、`scripts/combat/projectile.gd`、`scripts/combat/summon.gd`
- 判定原则：shell 无 description 字段，一律以 `mods` 为准；每个组合以"mods 是否被消费、是否产生与设计意图一致的行为"判定

## 0. 判定规则与代码消费路径

图例：

| 标记 | 含义 |
| --- | --- |
| ✅ 有效 | 外壳主体 mod 生效且与核心机制协同，符合设计意图 |
| ◐ 部分生效 | 外壳只有部分 mod 生效（通常是 damage_mult/cooldown_mult 乘区），主体 mod 失效或打折 |
| ✗ 无效 | 外壳功能对核心完全不生效（核心提前 return / 即时结算不消费），且无正向收益 |
| ⚠️ 语义冲突/重复 | 行为被替换、重叠或与设计意图矛盾（同点堆叠、轨道吞并、强制覆盖等） |

### 0.2 mods 合并顺序（旋风刃重点）

shell mods → wand shape_mods 覆盖（spell_caster.gd:126-137，后买覆盖冲突键）→ 旋风刃核心强制 `orbit_mods["orbit"] = 4.0`（spell_caster.gd:187，最后覆盖）。

## 2. 特殊核心与外壳的关系（mods 消费情况）

特殊核心在 `_cast` 中提前 return（spell_caster.gd:136-152），不走弹幕系统。外壳对它们**只可能消费两个乘区**：

| 核心 | 分支代码 | 消费的 mods | 不消费（外壳主体功能） | 额外注意 |
| --- | --- | --- | --- | --- |
| 传送 | `_cast_teleport` L212 | damage_mult（落点虚空爆炸伤害） | shots/spread/homing/pierce/bounce/orbit/explode/delay/split/drain | **aoe_mult 不生效**：爆炸半径固定 = core.aoe 48（L216），爆发外壳的"范围翻倍"落空 |
| 狂暴 | L139-141 | 无（不调用 _spell_damage） | 全部 10 个 mod | `_frenzy_left=3.0` 固定 3 秒；damage_mult 也无效；cooldown_mult 只惩罚自身槽 CD |
| 回响 | L143-146 | 无 | 全部 10 个 mod | **伪重置**：`_cast` 内把所有 `_cds[i]=0`，返回后外层 L49 又把自身槽 CD 赋回（连发=12s） |
| 圣光 | `_cast_blessing` L227 | damage_mult（光属性伤害） | 同上 9 个 | 治疗 15 固定不吃任何 mod；伤害半径固定 = core.aoe 90（aoe_mult 不生效） |
| 反制 | `_cast_counter` L239 | damage_mult（反制伤害） | 同上 9 个 | 弹幕销毁半径 + 伤害半径固定 = core.aoe 60（aoe_mult 不生效） |
| 召唤蝙蝠 | `_spawn_summon` L276 | damage_mult（召唤物伤害） | 同上 9 个 | summon.gd 按 max_count 静默中止（L92-93）；外壳伤害乘区直接套在召唤物上 |

**结论**：5 个"无弹幕"特殊核心 + 召唤，其外壳的有效内容 = 仅有 damage_mult（狂暴/回响连这个都没有）。连发/齐射/追踪/穿透/弹射/环绕/爆发/延时/分裂/吸血 的**主体功能全部不消费**，仅留下伤害乘区的增减——其中连发（0.8+CD×1.5）、齐射（0.7）、弹射（0.8）、环绕（0.75）还是负收益。

## 3. 按核心分组的问题清单

### 3.1 AOE 弹道核心：火球 / 冰锥 / 水弹 / 藤蔓（speed>0 且 aoe>0）

**问题 1：×穿透、×弹射 = 假外壳（4 核 × 2 外壳 = 8 组合）**
- 现状：`_scan_contact`（projectile.gd:128-145）中 `_aoe > 0.0` 时**首击接触即 `_explode_at` 并 return**，`_pierce_left`/`_bounce_left` 永远没有机会递减。
- 为什么有问题：玩家装了"穿透+2/弹射+2"，实际弹体第一下碰到敌人就爆炸消失，外壳主体 0 收益，反而白吃 0.85×/0.8× 伤害减伤。
- 建议（赋予语义，推荐）：在 projectile.gd `_scan_contact` 的 aoe 分支改为"爆炸后若 `_pierce_left > 0` 则不销毁、继续飞行（把 `_impacted` 拆成"已爆炸但仍在飞"），穿透数在后续接触中递减"；弹射同理可在爆炸后保留弹体进入反弹逻辑。实现位置：projectile.gd:134-145。若短期不动代码，应在槽位 UI 过滤"穿透/弹射 × 任意 aoe>0 核心"。

**问题 2：×环绕 = 弹道语义被替换（4 组合）**
- 现状：`_physics_process` 中 orbit 分支（projectile.gd:96-97）优先于飞行与瞬发，弹体变成绕玩家 2s 的接触球（半径 9px，L182-199），`_move_step`/`_scan_contact`/`_explode_at` 全部不执行。
- 为什么有问题：飞行+命中爆炸的核心身份消失，aoe 与 explode 失效；但 burn/slow/root/poison 状态与伤害仍生效——玩家预期"环绕的火球应该还能爆炸"，实际只能近身蹭伤。
- 建议：保留组合但把语义坐实——在 `_orbit_step` 命中敌人时若 `_aoe > 0` 则触发 `_explode_at`（让环绕弹体保留爆炸）；或直接过滤该组合。

**问题 3：×延时 = "滞空"而非"定点陷阱"（4 组合）**
- 现状：delay 在 spawn 点滞留 0.8s（projectile.gd:93-94）后才开始飞行。
- 为什么有问题：延时外壳的直觉语义是"弹到目标处再炸"；实际是**出生点悬停 0.8s**，期间敌人已走位，命中率下降；对瞬发核心才是真正的定点延迟。机制生效但语义错位。
- 建议：保留（数值上 1.3× 有补偿），在描述中注明"弹道在施法点滞留后发射"。

**问题 4：×连发 = 同线三发重叠（4 组合）**
- 现状：shots=3 且 spread=0，三发同方向同轨迹。
- 为什么有问题：单目标三连爆数值可观，但覆盖增益为零；与齐射（扇面）形成重复定位。
- 建议：保留（弹道核重叠可接受，作为单体爆发），不必改。

**问题 5：×分裂 = 小弹丢失显式状态（4 组合）**
- 现状：`_spawn_split_minis`（projectile.gd:307-337）硬编码 `status: {}`、`chain: 0`、`aoe: 0`、伤害×0.6。
- 为什么有问题：燃烧/减速/根缚/中毒 等显式状态不继承（冰锥小弹因元素隐式冻结、毒系因元素隐式 1 层毒除外），分裂出去的只是白板小弹。
- 建议：小弹继承 `_status`（保留根缚/减速等控场价值），实现位置：projectile.gd:317-327。

### 3.2 瞬发核心：闪电 / 毒雾 / 火柱 / 闪光（speed=0）

**问题 6：×追踪、×穿透、×弹射 = mods 完全不消费（4 核 × 3 = 12 组合）**
- 现状：`_physics_process` 瞬发分支（projectile.gd:99-102）直接落点爆炸，`_move_step` 永不执行；homing/pierce/bounce 三个 mod 无人读取（毒雾/火柱/闪光/闪电全中）。
- 为什么有问题：外壳只剩 0.85×/0.9×/0.8× 的负向乘区，"追踪/穿透/弹射"三个词在界面上纯属欺诈。
- 建议：过滤组合（UI 层按 core.speed==0 禁用 homing/pierce/bounce），或在商店权重里排除；赋予语义的成本高（瞬发无飞行段）。

**问题 7：×连发 = 同点堆叠浪费（4 组合，毒雾为确认案例）**
- 现状：shots=3、spread=0 → 三发在**同一落点**爆炸（各自独立结算，单点 3 倍伤害+3 倍状态层数），覆盖 0 增益。
- 为什么有问题：毒雾/火柱/闪电/闪光的定位是"区域控制"，连发把它们变成单点堆叠，范围价值全无；且毒雾 3 层毒、火柱 3×2 层燃会溢出。
- 建议：给连发加"落点扇面微偏"（复用 spread 逻辑，spread=0 时按 shots 在落点周边 ±10px 偏移），或对瞬发核过滤连发。实现位置：spell_caster.gd:172-178（瞬发时对每发位置加偏移）。

**问题 8：×环绕 = 区域核心被吞（毒雾/火柱/闪光，确认案例）**
- 现状：orbit 分支优先于瞬发 → 毒云/火柱/致盲爆发完全不再发生，变成绕玩家转的接触球（每次命中叠 1 层状态）。
- 为什么有问题：区域半径（48/64/90）与爆炸语义整体消失，只剩"9px 蹭伤"，核心价值被外壳吞掉。
- 建议：过滤（orb 分支前判断 `_instant` 则禁用 orbit），或坐实为"环绕时每 0.5s 在原落点释放一次小范围 AOE"。

**问题 9：闪电×环绕 = 半替换（电球保留链跳）**
- 现状：闪电+环绕 → 环绕电球，`_orbit_step`（projectile.gd:196-198）保留 `_try_chain`，但落雷 AOE 消失。
- 为什么有问题：核心的"区域落雷"没了，链跳变成从接触点起跳；行为怪异但非全废。
- 建议：同问题 8 处理（过滤或坐实）。

**问题 10：闪光×爆发 = aoe_mult 无效（盲爆半径恒 90）**
- 现状：`_explode_at`（projectile.gd:156-158）中盲爆半径 `radius = maxf(radius, 90)`；闪光 aoe=0 → aoe×2 后仍为 0 → 恒 90。
- 为什么有问题：爆发外壳承诺"范围翻倍"，对闪光完全不兑现；玩家还多付 1.3× CD。
- 建议：盲爆半径参与 aoe_mult（`radius = maxf(radius, 90 * aoe_mult)`，实现位置 projectile.gd:157），或给闪光数据补一个基准 aoe。

**问题 11：瞬发核心×分裂/吸血/延时/爆发/齐射 = 有效（20 组合）**
- 现状与证据：瞬发命中走 `_hit_enemy` → split/drain 生效（projectile.gd:201-226）；delay 在瞬发前判定 → 定点延迟爆（L93-99）；burst 的 aoe_mult 计入爆炸半径（spell_caster.gd:165）；齐射=扇面多点（L172-177）。
- 建议：保留，这是瞬发核的最优外壳方向。

### 3.3 旋风刃（whirl_blade）

**问题 12：×环绕 = 语义重复 + 白吃减伤（用户重点核查）**
- 现状：核心自带 2 刃绕身旋转；`_cast_whirl_blade`（spell_caster.gd:186-187）`orbit_mods = mods.duplicate()` 后强制 `orbit_mods["orbit"] = 4.0`——**外壳的 orbit=2 被直接覆盖**（合并顺序：shell → wand shape_mods → 核心 4.0 最后写），不叠加。
- 为什么有问题：装上环绕外壳后行为与不装**完全一致**（同样 2 刃、同样 4s、同样半径），却白吃 0.75× 伤害减伤；语义上"本体会旋转 + 环绕外壳"明显重复。
- 建议：过滤环绕外壳对该核心的售卖；若保留，应改为叠加（4+2=6 圈或加半径），实现位置 spell_caster.gd:187。

**问题 13：×分裂 = 小弹 1px/s 蠕动（bug）**
- 现状：旋风刃以 `speed=1.0` 生成弹体（spell_caster.gd:191），分裂小弹继承 `_speed if _speed > 0.0 else SPLIT_MINI_SPEED`（projectile.gd:325）→ 小弹速度=1.0px/s。
- 为什么有问题：小弹射程 45px 要走 45 秒，实际等于报废；这是"保底速度"判定把 1.0 当成正常速度的边界 bug。
- 建议（修复）：把速度判定改为"小于阈值一律用保底"（如 `_speed >= SPLIT_MINI_SPEED 或 _instant` 判据调整），实现位置 projectile.gd:325。

**问题 14：×爆发 = explode 永不触发（误导）**
- 现状：orbit 命中走 `_hit_enemy` 接触结算（projectile.gd:182-199），从不调用 `_explode_at`；aoe_mult 虽然计入 aoe（spell_caster.gd:185），但 aoe 在 orbit 路径无消费点。
- 为什么有问题：玩家预期"旋风刃+爆发=刀刃爆炸"，实际永远不炸；仅 1.2× 伤害与 1.3× CD 生效。
- 建议：坐实"接触命中触发小型爆炸"（_orbit_step 命中时 `_explode_at`），或过滤。

**问题 15：×连发/齐射 = 刃数不变，负向乘区**
- 现状：旋风刃分支忽略 shots/spread（始终 2 刃），连发还带 1.5× CD。
- 建议：赋予语义——连发=3 刃、齐射=5 刃（`_cast_whirl_blade` 的 `for i in 2` 改为读 shots），一行改动即可落地。

**问题 16：×追踪/穿透/弹射 = 不消费**
- 现状：orbit 分支不走 `_move_step`/`_scan_contact`，homing/pierce/bounce 无消费点（0.9×/0.85×/0.8× 白扣）。
- 建议：过滤；或穿透语义改为"轨道命中不计重复冷却"（改动较大，不建议）。

**问题 17：×延时 / ×吸血 = 有效（保留）**
- 证据：delay 在 orbit 分支前判定（projectile.gd:93-96）→ 0.8s 后开始旋转；吸血在 `_hit_enemy` 内（L218）→ 每次接触命中回血 10%。
- 建议：保留，并作为旋风刃的推荐外壳在 UI 提示。

**附加发现：数据字段 `pierce: true`（旋风刃）是死字段**——projectile 只从 mods 读 pierce（L62），核心字段不传入；且 orbit 命中路径本就不消费穿透。建议删除或实现。

### 3.4 召唤蝙蝠（summon_bat）

**问题 18：全部弹道外壳无效，只吃 damage_mult（确认案例）**
- 现状：`_spawn_summon`（spell_caster.gd:276-286）只把 `_spell_damage(core, mods, "summon")` 传给 summon.gd；shots/spread/homing/pierce/bounce/orbit/explode/aoe_mult/delay/split/drain 全部不消费。召唤上限由 summon.gd:92-93 按 max_count 静默中止。
- 为什么有问题：连发（0.8×+CD×1.5）、齐射（0.7×）、弹射（0.8×）、环绕（0.75×）是**纯负收益**——召唤物伤害变低且没有任何补偿；爆发/延时因 1.2×/1.3× 反而是唯一正向外壳（但"爆发/延时"的行为也不存在，只是乘区）。
- 建议：A. 赋予语义（推荐，改动小）：连发→按 shots 召唤多只（`_spawn_summon` 循环，配合 summon.gd 上限）；环绕→强制召唤 orb 类型（summon.gd 已有 orbit 技能）；爆发→强制召唤 fire_spirit（已有 self_destruct 技能）。B. 或按 damage_mult<1 过滤负向外壳。

### 3.5 特殊核心：传送 / 反制 / 圣光 / 狂暴 / 回响

**问题 19：传送/反制/圣光 × 全部外壳 = 仅 damage_mult（30 组合）**
- 现状：三者的 `_cast_*` 只调用 `_spell_damage`（spell_caster.gd:219/230/242），半径全部硬编码 core.aoe（48/60/90），不乘 aoe_mult；伤害结算不走 projectile，drain/split/delay 等全部无效。
- 为什么有问题：aoe_mult 行为与普通核心不一致（爆发外壳在特殊核上不放大范围），连发等负乘区外壳直接削弱主技能。
- 建议（赋予语义，落地位置 spell_caster.gd:212-251）：
  - 爆发：三处半径改为 `core.aoe * mods.aoe_mult * (1+area)`（各 1 行）；
  - 连发：传送→按 shots 连续闪现 N 段；齐射→落点扇面 N 连爆；
  - 延时：传送→落点延迟引爆（陷阱）；反制/圣光→延迟生效光环；
  - 吸血：爆炸命中回血（复用 `_hit_enemy` 的 drain 逻辑，把 take_damage 循环换成集中结算）。

**问题 20：狂暴 × 全部外壳 = 零消费（10 组合，P0 级误导）**
- 现状：分支（spell_caster.gd:139-141）设 `_frenzy_left=3.0` 即 return，`_spell_damage` 都不调用 → damage_mult 无效；连发/爆发还使自身槽 CD 变成 9s/7.8s。
- 为什么有问题：界面上任何外壳对狂暴都无意义，且连发直接惩罚核心（狂暴期望高频施放）。
- 建议：过滤全部外壳；或赋予语义——延时→狂暴持续 4s、爆发→1.5× 强度、吸血→狂暴期间击杀回血。

**问题 21：回响 × 全部外壳 = 零消费 + 自身槽伪重置（10 组合）**
- 现状：分支（spell_caster.gd:143-146）把所有 `_cds` 归零，但 `_cast` 返回后 L49 `_cds[i] = _cooldown_of(...)` 把**自身槽 CD 又赋回**——连发=12s、爆发=10.4s。
- 为什么有问题：回响"重置所有法术 CD"的承诺对自身槽不成立（先清零后写回），外壳的 CD 惩罚还直接放大自身冷却。
- 建议：修伪重置（分支内跳过自身槽，或在 L49 对 mana_echo 不再赋回，1 行）；外壳可赋予语义：延时→回响 2 次、吸血→回响时回血。

### 3.6 跨核心系统性问题

**问题 22：`explode` 标志是全项目死字段**
- 证据：`rg "explode"` 在 spell_caster.gd/projectile.gd 中只有函数名与注释，没有任何 `mods.get("explode")` 读取。爆发外壳实际 = aoe_mult + damage_mult + cooldown_mult，"爆炸"承诺不成立（对 aoe=0 的核心尤其明显）。
- 建议：实现该标志（explode=true 时即使 aoe=0 也在命中点生成基础半径爆炸），或从数据/UI 描述中删除。

**问题 23：`dot` 标志是死字段**
- 证据：毒雾 `dot: true` 无任何读取点；毒来自元素隐式状态（projectile.gd:236-238 `element=="poison"` 叠 1 层）。
- 建议：删除或让 dot 参与伤害计算（如 dot 核的爆炸伤害改按秒伤结算）。

**问题 24：特殊核心与普通核心的 mods 消费规则不一致**
- 证据：aoe_mult 只在 spell_caster.gd:165,185 消费；传送/反制/圣光半径硬编码。
- 建议：在 UI/商店对特殊核心标注"仅伤害乘区生效"，或统一消费规则。

**问题 25：merge 顺序易踩坑（shell → wand shape_mods → whirl 强制 orbit）**
- 证据：spell_caster.gd:126-137 后买覆盖；L187 核心覆盖。
- 建议：为 whirl_blade 去掉强制覆盖（改为叠加或直接过滤 orbit 外壳），并在数据层禁止 wand shape_mods 携带 orbit。
