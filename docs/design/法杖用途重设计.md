# 法杖用途重设计（55 把用途差异化，去范围堆叠）

> 2026-08-10 阶段任务产物。目标：解决用户反馈"法杖基本都是加范围的"——
> 原 55 把中 21 把携带 `aoe_mult`（38%），用途同质化；
> 重设计后 `aoe_mult` 仅 10 把（18.2% < 20%），每流派 5 把用途互异。

## 1. 调研来源（肉鸽游戏的"用途差异化"做法）

| 来源 | 借鉴点 | 本项目落地 |
|---|---|---|
| 吸血鬼幸存者（武器进化方向） | 每件武器进化后获得**独立身份**：范围系（圣水→火酒）、弹道系（鞭子→血鞭穿透）、召唤系（圣经→环绕圣物）、延时系（斧头→回旋斧）互不重叠 | 把"形态"拆成 12 种用途词：爆发/齐射/连射/穿透/环绕/弹射/分裂/延时/吸血/高速/强化/白板，每流派 5 把覆盖不同词 |
| 雨中冒险 2（物品形态） | 同一数值强化用不同**触发形态**表达：ukulele=链式传导、will-o-wisp=命中爆炸、ATG=额外火箭、剃刀=流血叠层；"形态决定手感，数值决定强度" | 同流派内用 shape_mods **键组合**区分形态（如毒系：贯穿/分裂/延时齐射/范围领域/分裂吸血 5 种完全不同手感） |
| 魔法工艺（容器/法杖合成） | 容器提供形态（弹道/轨道/延迟引爆），元素提供属性，二者正交组合 | 法杖 = shape（形态）× element_bonus（元素）× 数值（damage/cd），形态与元素解耦 |
| 本作《核心外壳组合审计》 | 150 组合审计给出 mods 消费路径与冲突清单（orbit 吞瞬发核、穿透对 aoe 核无效、召唤只吃 damage_mult 等） | 法杖 shape_mods **只使用被消费的键**，且不制造新的同类冲突（见 §4） |

## 2. 设计原则

1. **键白名单硬约束**：shape_mods 仅允许
   `shots / spread_angle / aoe_mult / speed_mult / pierce / bounce / split / delay /
   drain / orbit / damage_mult` 11 键（spell_caster.gd 消费键）；
   移除原表死键 `slow_power`（全项目无消费点）；禁止 homing/explode（消费存在但不在白名单）。
2. **aoe_mult 去堆叠**：从 21 把（38%）压到 10 把（18.2%）。保留 aoe 的法杖均为
   "范围是核心身份"的形态：爆发（烈焰/重击/极寒/圣盾）、延时范围（火雨/霜冻/毒雾）、
   潮汐、深水）。其余范围需求改用 齐射（扇形铺开）/ 分裂 / 弹射 / 环绕 表达。
3. **每流派用途互异**：同流派 5 把的 (shape, shape_mods 键组合) 指纹互异 ≥ 3
   （实际 10 个流派 5 种、召唤 4 种）。
4. **传说独特**：11 把传说的指纹两两互异，且收益明显高于稀有档（高数值 + 双机制）。
5. **desc 一致性铁律**：description 逐条与 shape_mods / damage_mult / cd_mult /
   element_bonus 的实际效果对应（由 test_wands.py 关键词断言强制）。
6. **元素归属**：element_bonus 与 school 对应（火→fire、冰→ice、雷→lightning、
   毒→poison、召唤→summon、水→water、风/暴击→无元素、防御→light、诅咒→void、
   近战→blade），修正原霜冻法杖"冰校给水加成"的越界。
7. **稀有度分层与价格带不变**：普通 21 / 稀有 23 / 传说 11，价格 120-260 / 300-600 /
   700-1200。
8. **保留契约**：id / name / school / icon 全部保留；保留 basic_wand 学徒法杖
   （none 形态，白板）。

## 4. 与《核心外壳组合审计》的冲突规避

审计结论的消费事实与本次落地对应：

| 审计问题 | 规避措施 |
|---|---|
| 穿透/弹射对 aoe>0 弹道核首击即爆（问题1） | 穿透类法杖（冰锥/连锁/雷霆/腐蚀/战刃等）不携带 aoe_mult，保证"贯穿"兑现；范围类法杖不携带 pierce/bounce |
| 环绕吞瞬发核/旋风刃强制覆盖 orbit（问题8/12/25） | orbit 法杖从 5 把压到 3 把（冰环/环绕/漩涡），且**旋风法杖不再用 orbit**——改走 shots（旋风刃 3 刃，spell_caster 已支持） |
| 旋风刃×分裂小弹 1px/s（问题13） | 旋风法杖不带 split |
| 召唤核心只消费 shots/damage_mult/cd_mult（问题18） | 召唤 5 把只使用 shots / damage_mult / cd_mult / summon 元素加成，不携带其他死键 |
| 瞬发核×追踪/穿透/弹射零消费（问题6） | 法杖表整体不提供 homing；穿透类描述均面向弹道核心 |
| 特殊核心（传送/圣光/反制）aoe_mult 已接入（审计建议落地） | 圣盾/圣光等法杖的 aoe/drain 描述与 spell_caster._cast_blessing/_cast_counter 的现行实现一致 |
| explode/dot 死字段 | 不使用；爆发一律用 aoe_mult+damage_mult 表达（与代码消费一致） |
