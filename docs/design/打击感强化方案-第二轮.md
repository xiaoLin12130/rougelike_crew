### 2.4 维度对比结论表

| 手段 | Brotato | RoR2 | VS | **本项目现状（代码证据）** |
|---|---|---|---|---|
| hitstop | 无（快节奏） | 命中 1~2 帧+暴击强化 | 仅重武器 | 仅 5 处 synergy 发 `fx_hit_slow`（summon/curse/wind），projectile/melee 普通攻击未接 |
| 击退 | 武器差异化 | 受击硬直 | 无 | `KNOCKBACK=90`、decay=10 → 总位移约 9px（玩家 32px 的 28%），几乎无感 |
| 尸体 | 碎块+血迹 | 碎块+掉落光束 | 碎块/血雾 | `_die()` emit 后直接 queue_free，无任何死亡视觉 |
| 数字 | 可选/克制 | 聚合+暴击弹跳 | 高频降噪 | 无上限/无聚合/无弹出（`_on_damage_dealt` 每跳 new） |
| 震屏 | 克制 | 分级 | 几乎不用 | `shake(power)` 固定 0.15s，无分级无冷却 |
| 慢动作 | 无 | 精英/Boss 击杀 | Boss 击杀 | 仅连杀 ≥6/2s → 0.8x/0.15s |
| 音效 | 核心（每武器独立） | 核心+变调 | 核心 | assets/audio 7 个 ogg 存在但战斗路径零调用 |
| 命中粒子 | 有 | 有 | 轻量 | 无方向（fx_hit 无 dir 参数）、普通命中无节流 |

### 2.5 结论：低成本高感知手段排序

三款游戏的共性：**打击感基石 = 音效 + 死亡反馈 + 伤害数字**；hitstop / 震屏 / 慢动作是"点缀"，且必须分级（只给暴击/击杀/大怪，否则高频战斗被淹没）。

按「感知提升 / 实现成本」从高到低：

1. **命中/击杀音效（含随机变调）** —— 成本最低、感知最强（声音是打击感的一半）
2. **死亡碎块/爆散** —— 一次接入，每杀必反馈
3. **伤害数字聚合 + 上限 + 弹出动画** —— 降噪 + 爽感双收
4. **暴击差异化**（数字+音效+hitstop+金色环）—— 暴击是"爽点"
5. **hitstop 接入普通攻击路径**（暴击/大怪触发）
6. **击退 + 受击硬直提升**
7. **震屏分级 + 方向 + 冷却**
8. **命中粒子方向化**
9. **击杀慢动作细化**（精英/Boss/连杀三档）
10. **玩家受击反馈**（红晕 + 方向震，与"打敌人"对称）

## 三、现状盘点：第一轮已落地 vs 关键缺口

### 3.1 第一轮已落地（代码确认）

| 项 | 现状（以函数名为准） |
|---|---|
| 闪白 | enemy.gd `_flash()` + `_apply_status_visual()` 统一 `spr.modulate`（与状态着色合并）；fx_manager `_on_fx_hit_flash` 仍对根节点闪白（玩家通道保留） |
| 击退 | enemy.gd `_knock_vel`（velocity 衰减式，`KNOCKBACK=90`、`KNOCKBACK_DECAY=10`），root/freeze 清零，精英/Boss 免疫 |
| hitstop | fx_manager `_on_fx_hit_slow`：0.05 因子 / 0.06s / 冷却 0.15s（复用 `_on_slow_mo` time_scale 控制器） |
| 慢动作 | 连杀 ≥6/2s → 0.8x/0.15s + 闪电爆 |
| 震屏 | camera_shake.shake(power)，固定 0.15s，新震杀旧震 |
| 伤害数字 | DamageNumber：14px、暴击 1.6x 金色、上飘 18px、±6px 抖动、0.6s 寿命；DOT 字 0.8x |
| 暴击反馈 | 金色 burst 14~22 粒 + shake 2.0 |
| DOT 节流 | fx_dot_text 由调用方 0.35s 节流 |
| 构筑光环 | player_aura.gd（档位 0-3，元素流/雷云/冰晶已有雏形） |

### 3.2 关键缺口（"打击感仍然差"的根因，含证据）

1. **无命中音效**：`sfx_bus.play()` 在 projectile / melee_attack / enemy.take_damage 战斗路径**零调用**（grep 确认）。三款参考游戏全部把音效列为第一反馈。
2. **hitstop 未接普通攻击**：`fx_hit_slow.emit` 全仓仅 5 处（summon.gd:475、curse_synergy.gd:201/223、summon_synergy.gd:528、wind_synergy.gd:455/732）；`projectile._hit_enemy`、`melee_attack._swing` 暴击不触发 → 玩家 90% 的命中（弹道/近战）无停顿。
3. **伤害数字无上限**：`_on_damage_dealt` 每跳 `DamageNumberScene.instantiate()`，无存活数/帧率上限 → 高攻速刷屏 = 廉价感（性能文档热点 2 同源）。
4. **击退位移约 9px**：`90 / 10 = 9px`，仅为玩家宽 28%，且无受击硬直（无挤压/倾斜），视觉上"没被打飞"。
5. **尸体直接消失**：`_die()` → `EventBus.enemy_died` → `queue_free()`，无碎块/残骸/血迹。
6. **震屏无分级**：普通命中 0（好），但暴击 2.0 与爆炸 3.0、Boss 死 12 全部 0.15s 同时长，大事件没有"更久更沉"。
7. **命中粒子无方向**：`fx_hit(pos, kind)` 无 dir，粒子全向溅射，打谁都一样。
8. **玩家受击反馈弱**：仅根节点闪白 + shake 2.5，无红晕/方向提示。

## 四、强化清单（按性价比排序，前 10 项）

> 每条标注：改动文件 / 实现方式 / 具体参数 / 预期收益 / 风险。全部沿用第一轮的 `juice_*` 开关体系与 `GFEEL_*` 常量区约定，新增项默认接入 `juice_level`。

### G-1 命中音效系统（S 级，性价比第 1）

- **改动文件**：scripts/core/sfx_bus.gd、scripts/combat/projectile.gd、scripts/combat/melee_attack.gd、scripts/combat/summon.gd、scripts/enemies/enemy.gd（玩家受击）、scripts/fx/fx_manager.gd（击杀音）
- **实现方式**：
  1. SfxBus 建 16 个 AudioStreamPlayer 池轮换（替代每次 new），`play_hit(kind: String, crit: bool)` 入口；
  2. 命中音映射表（初版，试听后调）：普通命中 `sfx_zap.ogg` -10dB；暴击 `sfx_laser2.ogg` -6dB、pitch +0.15；击杀 `sfx_two_tone.ogg` -8dB；玩家受击 `sfx_shield_down.ogg` -8dB；护盾 `sfx_shield_up.ogg`；Boss 命中 `sfx_laser1.ogg` 降调 -0.15、-4dB；元素命中按 kind 微调 pitch（fire +0.05 / ice -0.05 / lightning +0.1 / poison -0.1）；
  3. 随机变调：`pitch_scale = base * randf_range(0.88, 1.12)`；
  4. 节流：`HIT_SFX_MIN_INTERVAL = 0.04s`（同 kind 全局）；
  5. 调用点：projectile `_hit_enemy`、melee `_swing`、summon 攻击、`_on_enemy_died`（击杀音）、`_on_player_hit`。
- **预期收益**：打击感单项最大提升（参考游戏全部把音效放第一位）；零新资产（7 个 ogg 复用）。
- **风险**：映射听感可能不贴 → 初版默认 -10dB 起步，A/B 试听后再定映射；节流防爆音。

### G-2 死亡碎块爆散（S 级，性价比第 2）

- **改动文件**：scripts/fx/fx_manager.gd（`_on_enemy_died` 扩展）、scripts/enemies/enemy.gd（可选：传死亡方向）
- **实现方式**：
  1. `_on_enemy_died(id, pos, xp, gold, elite)` 内追加死亡演出（不阻塞现有连杀逻辑）：
     - 碎块层：6~10 粒 `spark_01/slash_02/dirt_02` 贴图粒子，scale 0.05~0.12，vel 120~260 全向，grav (0, 300)，life 0.35~0.6s，颜色=敌人元素色或暗红 `Color(0.75,0.28,0.2)`；
     - 扩散环：小环 `[1.4, 0.18, 1.8]`；
     - 闪光：`light_01` 0.2s；
  2. elite 翻倍（12~18 粒 + 金色环）；Boss 死亡走现有大爆（不动）；
  3. 上限：与 `HIT_FX_BURST_MAX` 共用节流（击杀连发场景不超 24 次/s）；每死亡粒子 ≤ 18。
- **预期收益**：每杀一怪都"爽一下"，是 VS/RoR2 最高频反馈；一次接入全局生效。
- **风险**：粒子量控制（复用现有节流/上限体系）；不影响伤害与掉落。

### G-3 伤害数字聚合 + 上限 + 弹出（S 级，性价比第 3）

- **改动文件**：scripts/fx/fx_manager.gd（`_on_damage_dealt`）、scripts/fx/damage_number.gd
- **实现方式**：
  1. 上限：`DMG_NUM_MAX_ALIVE = 24`（超限时最老数字加速淡出 0.15s）；`DMG_NUM_PER_FRAME = 8`（同帧超出合并）；
  2. 聚合：同帧同位置（距离 < 14px）命中 → 数字叠加到最近一个（`+N`），RoR2 同款降噪；
  3. 弹出：`play()` 增加 overshoot —— scale 0.6 → 1.15 → 1.0（0.18s，EASE_OUT），上飘改 QUAD OUT 保持；
  4. 暴击差异化：1.8x、随机横移 ±10px、旋转 ±4°、颜色 `Color(1.0,0.84,0.2)`（保持）。
- **预期收益**：高攻速下数字从"刷屏"变"聚合+弹出"，可读性与爽感双升；顺带解决性能文档热点 2。
- **风险**：聚合条件过宽会把独立命中误合并 → 用同帧+距离双条件；不改变伤害逻辑。

### G-4 hitstop 接入普通攻击（S 级，性价比第 5）

- **改动文件**：scripts/combat/projectile.gd（`_hit_enemy`）、scripts/combat/melee_attack.gd（`_swing`）、scripts/combat/summon.gd（攻击分支）
- **实现方式**：`crit == true or target 是 Boss/精英` 时 `EventBus.fx_hit_slow.emit(target)`；复用 fx_manager 已有 `_on_fx_hit_slow`（0.05/0.06s/0.15s CD，无需新逻辑）。Boss 命中可加参数字段（factor 0.05 / 0.08s，由 `_on_fx_hit_slow` 判 `target.is_boss`）。
- **预期收益**：弹道/近战暴击有了"卡肉感"，补上第一轮唯一没接的路径；每处改动 1~2 行。
- **风险**：高频暴击连发不叠加（已有 0.15s CD）；不改判定。

### G-5 击退提升 + 受击硬直（A 级，性价比第 6）

- **改动文件**：scripts/enemies/enemy.gd（`take_damage`、`_physics_process`、`_apply_status_visual`）
- **实现方式**：
  1. `KNOCKBACK 90 → 150`（位移约 15px，约玩家宽 47%）；暴击 `×2.0`（300 → 约 30px，明显"打飞"）；精英/Boss 免疫保留；root/freeze 清零保留；
  2. 新增受击硬直视觉（纯视觉）：命中瞬间 `spr.scale = 1.08` 挤压 0.08s 回弹（Tween EASE_OUT），或 `rotation ±5°` 回弹 0.1s（与 `_flash` 同帧触发，互不冲突）；
  3. 体型补偿保留：`power / (1 + 0.5 * (scale.x - 1))`。
- **预期收益**：命中反馈从"数字"升级为"位移+形变"，Brotato 式"武器性格"的雏形。
- **风险**：位移变大可能推怪出 arena → 沿用 arena clamp；击退不参与碰撞的既有约束不变。

### G-6 震屏分级 + 方向 + 冷却（A 级，性价比第 7）

- **改动文件**：scripts/fx/camera_shake.gd（`shake`）、scripts/fx/fx_manager.gd（各触发点传参）
- **实现方式**：`shake(power, duration = 0.15, priority = 0, dir := Vector2.ZERO)`；
  - 振幅-时长表：普通命中 0（不震）；暴击 2.0/0.12s；Boss 命中 3.5/0.22s；Boss 死亡 12/0.5s（现有 12 延长）；爆炸 3.0/0.18s；玩家受击 2.5/0.2s；
  - 优先级：新 shake 仅当 priority ≥ 当前或冷却已过才生效；`SHAKE_COOLDOWN = 0.08s` 同帧取最大；
  - 方向性：`offset = rand * power * (0.7 垂直 + 0.3 沿 dir)`，玩家受击时朝受击反方向偏 30%（可选，先做幅度/时长分级）。
- **预期收益**：大事件"更久更沉"，小事件不刷屏；方向性为后续升级留接口。
- **风险**：Boss 死 0.5s 震屏需实测不晕（竖屏手机尤其）→ 可加 Settings 档位关闭。

### G-7 命中粒子方向化 + 暴击环（A 级，性价比第 8）

- **改动文件**：scripts/core/event_bus.gd（`fx_hit` 加可选 `dir := Vector2.ZERO`，向后兼容）、scripts/combat/projectile.gd、scripts/combat/melee_attack.gd、scripts/fx/fx_manager.gd（`_on_fx_hit`）
- **实现方式**：
  1. 命中方传 `(enemy.pos - player.pos).normalized()`（若玩家为 null 传 ZERO）；
  2. `HIT_RECIPES` 粒子一半改为沿 dir 的 50° 锥形溅射（`direction=dir`、`spread=50`），另一半保持径向 → "从玩家方向打过去"的指向感；
  3. 暴击追加小型扩散环（复用 `_spawn_ring`，参数 `[1.6, 0.18, 1.8]`，金色）；
  4. 节流：`HIT_FX_MIN_INTERVAL = 0.03s`（按 kind）、`HIT_FX_BURST_MAX = 24次/s`（tier≥2 时减半）。
- **预期收益**：命中方向可读（当前打谁都一样的最大痛点之一）。
- **风险**：纯参数/默认参改造，旧调用不受影响。

### G-8 击杀慢动作细化（A 级，性价比第 9）

- **改动文件**：scripts/fx/fx_manager.gd（`_on_enemy_died`）
- **实现方式**（三档，均复用 `_on_slow_mo`）：
  - 普通连杀：保留（≥6/2s → 0.8x/0.15s）；
  - 精英击杀：0.6x/0.12s + 金色环（`fx_explosion "gold"` 已存在）；
  - Boss 击杀：0.35x/0.4s + 震屏 12/0.5s（与 G-6 联动）+ 全屏白闪 0.2s（可选，CanvasLayer 白矩形 alpha 1→0）；
  - 冷却：`KILL_SLOW_CD = 1.0s` 防多杀连发叠加。
- **预期收益**：Boss/精英击杀的"仪式感"（RoR2 同款）。
- **风险**：慢动作滥用拖节奏 → 仅三档且带 CD。

### G-9 玩家受击反馈强化（B 级，性价比第 10）

- **改动文件**：scripts/fx/fx_manager.gd（`_on_player_hit`）、可选 scenes/ui 红晕节点
- **实现方式**：
  1. 受击方向微震：`screen_shake(2.5, 0.2, 1, dir)`（G-6 扩展后支持）；
  2. 全屏红晕：CanvasLayer + ColorRect（或程序化 `_draw` 边缘渐变）`Color(0.8,0.08,0.08, 0.35 → 0)` 0.25s，低血量（<30%）时增强到 0.5；
  3. 无敌帧闪烁保留（现有）。
- **预期收益**：与"打敌人"对称的痛感反馈。
- **风险**：红晕需可关闭（Settings，防误伤观感）。

### G-10 音画时序统一（B 级，收尾项）

- **改动文件**：scripts/fx/fx_manager.gd（`GFEEL_*` 常量区 + `_on_fx_hit_slow` / `_on_damage_dealt` / `_on_screen_shake`）
- **实现方式**：反馈链时序约定——hitstop 触发帧：音效立即（0ms）→ 闪白延长 1.2x → 数字延迟 0.03s 弹出（停顿结束后数字才出现，阅读顺序正确）→ 震屏同帧；所有参数集中到 fx_manager 顶部 `GFEEL_*` 常量区，`juice_level` 一键开关。
- **预期收益**：反馈"起承转合"完整，避免各模块各自为政的错位感。
- **风险**：纯调度层，无机制风险。

## 七、结论

- 第一轮已建好地基（闪白/击退/hitstop/震屏/慢动作/数字全有），**"仍然差"的根因是四件事没接**：战斗路径零音效、hitstop 未接普通攻击、死亡无反馈、数字无上限无聚合。
- 按性价比先做 **G-1 音效 → G-2 死亡碎块 → G-3 数字聚合 → G-4 hitstop 接入**（S 级，各 0.5~1 天），再做 A 级四项；全部为纯视觉/音频层改动，不碰判定与数值，风险可控。
