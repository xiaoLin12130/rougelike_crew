## 零、结论摘要（TL;DR）

1. **能做，引擎已原生支持且本项目机制已在用**：`enemy.gd` 的 `_build_sprite()` 已经用 AnimatedSprite2D + SpriteFrames 播放帧动画（现有全部 15 种怪都是 2~3 帧 idle 动画，只是帧少、视觉上接近平移）。
2. **野猪图集实测帧宽是 48px 而不是 32px**：Run/Walk = 288x32 = **6 帧**（不是 9 帧），Idle/Hit = 192x32 = **4 帧**（不是 6 帧）。已用像素自相关 + 项目切割脚本预设（`cut_assets.py` 里 `/Mob/Boar/ → 48,32,GRID`）双重验证。
3. **Hit 表 4 帧完全相同**（PIL 逐帧对比），没有真实受击动画，不必接入；Run/Idle/Walk 各帧全部不同，可直接切帧。
4. **接入成本很低**：切帧（工具已有）→ 放 `assets/sprites/enemy/` → enemies.json 加条目 → enemy.gd `_build_sprite` 扩展多动画 + 按速度阈值切 idle/run（约 20~30 行小改，不动任何现有行为）。
5. **建议先做 P0**：野猪 Run(6帧)+Idle(4帧) 动画 + 移动方向 flip_h（侧视四足素材必须翻转，否则倒着跑）。

## 一、Godot 2D 帧动画官方要点（来源：项目本地官方文档缓存 `.tools/godot-docs`，RST 源码，4.7 版）

> 外网不可达（curl 官方站点失败），以下均出自本地缓存：
> `.tools/godot-docs/tutorials/2d/2d_sprite_animation.rst`、`classes/class_animatedsprite2d.rst`、`classes/class_spriteframes.rst`

### 1.1 AnimatedSprite2D + SpriteFrames（本项目已采用，是官方推荐做法）

- 官方教程明确：单张图片集合与整张精灵表**两种来源都能用 AnimatedSprite2D 做动画**。
- 精灵表在编辑器 SpriteFrames 面板用"Add frames from a Sprite Sheet"按行列切帧加入动画；本项目不走编辑器，而是**代码构建 SpriteFrames**（`enemy.gd` / `player.gd` 都是 `SpriteFrames.new()` + `add_animation` + `add_frame`），一样是官方支持路径。
- 代码控制：`play(name)` / `stop()` / `pause()` / `play_backwards()`；`speed_scale` 是全局倍速（可做冲刺加速动画）；编辑器里可用 `autoplay` 属性自动播放（代码里 `play()` 等效）。

### 1.2 SpriteFrames 关键 API（本地类文档核实）

| API | 语义 | 备注 |
|---|---|---|
| `add_animation(anim)` | 新增动画槽（"idle"/"run"/"walk"...） | 现有代码只加了 "idle" |
| `add_frame(anim, texture, duration=1.0, at_position=-1)` | 追加帧；`duration` 是相对时长（1.0=按动画 FPS） | 多动画时按序追加即可 |
| `set_animation_speed(anim, fps)` | 该动画 FPS（6.0 = 每秒 6 帧） | 现有 idle 用 6.0 |
| `set_animation_loop(anim, bool)` | 是否循环 | **4.x 已弃用**，官方建议用 `set_animation_loop_mode(anim, LOOP_NONE/LOOP_LINEAR/...)`（player.gd 仍在用旧 API，兼容但建议新代码用新 API） |
| `get_frame_texture(anim, i)` / `remove_frame` / `clear` / `get_animation_names` | 查询/增删 | — |

### 1.3 信号（做"播放完成"类逻辑用）

- `animation_finished`：非循环动画播到末尾时发出并**自动暂停**；**循环动画不触发此信号**。
- `animation_looped`：循环动画每转一圈发一次。
- `frame_changed`：换帧时发（可做踩点音效/命中帧）。
- 注意：`play()` 在 AnimatedSprite2D 上是立即生效的（官方教程里"play 延迟到下一帧"的坑只针对 AnimationPlayer）。

### 1.4 另一种方式：Sprite2D hframes/vframes + AnimationPlayer（备选，不建议本项目用）

- 官方教程第三部分：Sprite2D 设 `hframes/vframes` 把整张表切成网格，用 `frame` 属性选格，AnimationPlayer 动画化 `frame` 实现播放。
- 优点：单张贴图、编辑器可视化；缺点：每怪要挂 AnimationPlayer + 动画资源，运行时热构建麻烦。本项目已有 AnimatedSprite2D 机制，**保持现状即可**。
- 代码侧若想"不切文件、直接引用整表"，可用 `AtlasTexture`（region 指向 sheet 中每帧矩形）作为 `add_frame` 的 texture——可行但不如切帧直观，本项目工具链已支持切帧，不推荐。

### 1.5 性能注意（官方 + 项目缓存手册核实）

- AnimatedSprite2D 每帧**只画当前帧**，多帧 = 每怪只多占纹理引用、不多画调用；场上敌人 ≤32（`_tick_separation` 注释），6 帧 48x32 图对性能无影响。
- Godot 4 Canvas 自动合批：同纹理同参数可合批；每帧独立 PNG（6 张不同纹理）比整表 AtlasTexture（1 张纹理）多纹理切换，但对 32 怪规模可忽略；贴图总量（6×48×32×4B ≈ 36KB）可忽略。
- 本项目已设像素关键项（project.godot 实测）：`default_texture_filter=0`（Nearest）、`snap_2d_transforms_to_pixel=true`、`snap_2d_vertices_to_pixel=true`——新贴图无需额外处理；导入时确认 Filter=Nearest、关 Mipmaps（手册 1.1 节）。

### 1.6 常见坑清单（本地手册 godot-pitfalls.md + 类文档）

1. 像素模糊 → 项目已 Nearest，OK。
2. `set_animation_loop` 弃用警告 → 新代码用 `set_animation_loop_mode`。
3. `animation_finished` 对循环动画不触发 → 做"播完切状态"要先把该动画设为 LOOP_NONE。
4. 速度语义：`set_animation_speed` 单位是 FPS 不是倍速；6 FPS 双帧动画 = 每秒闪 3 次（现怪偏抽搐），多帧后 6 FPS 更自然。
5. `_process/_physics_process` 里不要反复 `$`/get_node，缓存节点（手册 3.5 节）；动画切换用缓存引用。
6. 帧图集 vs 单帧文件：对 48x32 小图差异可忽略；若将来用大图集（Retro-Lines Enemies.png 整表），优先 AtlasTexture 或切帧，别用 Sprite2D+AnimationPlayer 硬刚。

## 二、项目现状评估（读码 + 实测）

### 2.1 enemy.gd 动画机制现状（`_build_sprite()`）

```gdscript
func _build_sprite() -> void:
    var frames: int = int(conf.get("frames", 2))
    var base_path: String = str(conf.get("sprite", ""))
    var anim := AnimatedSprite2D.new()
    anim.name = "AnimatedSprite2D"
    anim.sprite_frames = SpriteFrames.new()
    anim.sprite_frames.add_animation("idle")
    anim.sprite_frames.set_animation_speed("idle", 6.0)
    for i in frames:
        var p := base_path.replace("_1.png", "_%d.png" % (i + 1)) if frames > 1 else base_path
        anim.sprite_frames.add_frame("idle", load(p))
    ...
    anim.play("idle")
    add_child(anim)
```

数据侧（`data/enemies.json` 实测）：15 种小怪，字段 `sprite: "res://assets/sprites/enemy/xxx_1.png"` + `frames`（默认 2，slime=3、mimic=4）；代码把 `_1.png` 替换成 `_2.._N.png` 循环加载。

### 2.2 支持度评估（逐项确认）

| 问题 | 现状 | 结论 |
|---|---|---|
| 是否只有 idle 动画？ | 是，`add_animation("idle")` 唯一动画，全文件无第二动画 | 需要扩展 |
| 能否扩展多动画？ | 能。SpriteFrames 原生支持多动画；`player.gd` 已有 4 方向 × 2 帧多动画先例（`_build_frames()`：`add_animation(dir)` + `set_animation_speed` + `set_animation_loop` + `add_frame`） | 直接可行 |
| 移动方向翻转 flip_h？ | **无**。enemy.gd 全文搜不到 `flip_h`/`flip_v`；现在怪无双方向需求（正视图素材），但野猪是侧视图素材，**必须补** | 需要小改 |
| 状态切换（idle→run 按速度）？ | 无。`_physics_process` 里没有动画状态机 | 需要小改 |
| 动画速度/播放完成信号？ | 只有 `set_animation_speed("idle", 6.0)` + `play("idle")` | 按需用 |
| 引擎层/场景层改动？ | `enemy.tscn` 只有 CharacterBody2D + CollisionShape，AnimatedSprite2D 纯代码创建 | 无需动场景 |

**评估结论：引擎 100% 支持，缺的只是 enemy.gd 的"多动画加载 + 状态切换 + flip_h"三个小功能点（合计约 20~30 行），且全部可做成向后兼容（无 `anims` 字段的旧怪走原逻辑）。**

### 2.3 其他相关现状

- 受击闪白已有（`_flash()` modulate 白闪），死亡爆炸特效已有——受击动画非必需。
- 精英金色色调、状态色调都是 modulate 叠加在 AnimatedSprite2D 上，与多帧动画兼容。
- `_sprite_content_offset()` 只对宽 >64px 的贴图做重心偏移；48px 帧内容已基本居中（见 3.3），无需处理。

## 三、野猪图集实测（PIL 像素级，全部 4 张表）

素材位置：`.tools/user_assets/Legacy-Fantasy - High Forest 2.0/Legacy-Fantasy - High Forest 2.3/Mob/Boar/`

### 3.1 帧宽修正（重要）

用户原以为是 288x32=9 帧、192x32=6 帧（按 32px 猜）。**实测帧周期 = 48px**（列 alpha 剖面自相关最优周期 48，且项目已有脚本 `.tools/asset_clips/_scripts/cut_assets.py` 对 `/Mob/Boar/` 预设了 `48, 32, GRID`，双重确认）：

| 表 | 尺寸 | 帧数 | 每帧画布 | 帧内容 bbox | 各帧是否不同 |
|---|---|---|---|---|---|
| Run | 288x32 | **6 帧** | 48x32 | x4-42, y2-31 | 6 帧全不同 ✅ |
| Idle | 192x32 | **4 帧** | 48x32 | x0-41, y5-31 | 4 帧全不同 ✅ |
| Walk | 288x32 | **6 帧** | 48x32 | x0-42, y5-31 | 6 帧全不同 ✅ |
| Hit | 192x32 | 4 帧 | 48x32 | x6-40, y2-31 | **4 帧完全相同 ❌（无真实受击动画，跳过）** |

### 3.2 变体选择

每动作有 3 个变体：默认（棕）、`-Black`（深色+深描边）、`-White`（亮色）。PIL 验证：三变体 **alpha 完全一致，仅调色不同**，帧布局相同。Idle 的深色变体名为 `Idle-Sheet-export-Back.png`（命名是导出残留，内容即黑描边版，均值色与 Run-Sheet-Black 一致）。

**建议用 Black 变体**（`Run-Sheet-Black.png`、`Idle-Sheet-export-Back.png`、`Walk-Base-SheetBlack.png`）：深描边与游戏现有 Retro-Lines/程序化怪的画风一致。

### 3.3 对齐与缩放

- 每帧内容水平居中（center x≈23 vs 画布中心 24，偏差 ≤1px 且各帧一致，动画播放稳定）；y 向底对齐（脚踩底边）。
- 帧画布 48x32 比现有 32x32 怪略宽——视觉上野猪就是大体型怪，可接受；若要与其他怪同尺寸，落地时可用 `size: 0.7`（enemies.json 已有 size 字段，scale 生效）或切帧时贴 32x32 画布（内容缩放 0.8 会破坏像素网格，**不推荐缩放，用 size 字段即可**）。
- 碰撞体是半径 8 的圆（enemy.tscn），视觉变大不影响判定。

## 四、野猪接入方案（落地步骤，待用户确认后执行）

### 4.1 切帧（工具已有，零新代码）

```powershell
python tools/scripts/cut_atlas.py ".tools/user_assets/Legacy-Fantasy - High Forest 2.0/Legacy-Fantasy - High Forest 2.3/Mob/Boar/Run/Run-Sheet-Black.png" --out assets/sprites/enemy --pitch 48 --name seq --prefix boar_run
# 同理：Idle-Sheet-export-Back.png → boar_idle（4 帧）、Walk-Base-SheetBlack.png → boar_walk（6 帧）
# 产出：boar_run_0..5.png / boar_idle_0..3.png / boar_walk_0..5.png（seq 命名按行优先顺序，单行表即帧序）
```

> 注意：`cut_atlas.py` 默认 `--name seq` 输出 `{stem}_{n}.png`；落地时把前缀命名为 `boar_run` 等，避免与现有 `xxx_1.png` 双帧命名冲突。Hit 表 4 帧全同，**不切**（受击表现沿用现有 `_flash()` 白闪即可）。

### 4.2 enemies.json 配置（新增 boar 条目，扩展可选字段）

```json
{
  "id": "boar",
  "name": "野猪",
  "sprite": "res://assets/sprites/enemy/boar_idle_0.png",
  "frames": 4,
  "speed": 96,
  "behavior": "charge",
  "anims": {
    "idle": { "prefix": "res://assets/sprites/enemy/boar_idle", "frames": 4, "fps": 5.0 },
    "run":  { "prefix": "res://assets/sprites/enemy/boar_run",  "frames": 6, "fps": 10.0 },
    "walk": { "prefix": "res://assets/sprites/enemy/boar_walk", "frames": 6, "fps": 8.0 }
  }
}
```

- `sprite`+`frames` 保留（旧逻辑兜底），`anims` 为新字段；**旧怪无 `anims` 时走原逻辑，100% 向后兼容**。
- 动画命名规范：`boar_idle`、`boar_run`、`boar_walk`；`anims` 字段缺失或某动画帧文件缺失时回退（跳过该动画，保留 idle）。

### 4.3 enemy.gd 最小改动方案（仅示意，不落地）

在 `_build_sprite()` 中：存在 `conf.anims` 时按 `anims` 字典建多动画（`add_animation` + `set_animation_speed` + `set_animation_loop_mode(LOOP_LINEAR)` + 循环 `add_frame`，帧文件命名 `{prefix}_{i}.png`），否则走原单 idle 逻辑。另加：

```gdscript
# 状态切换（_physics_process 末尾，速度阈值版）
var anim := get_node_or_null("AnimatedSprite2D") as AnimatedSprite2D
if anim and anim.sprite_frames.has_animation("run") and anim.sprite_frames.has_animation("idle"):
    var spd := velocity.length()
    var want := "run" if spd > 10.0 else "idle"
    if anim.animation != want:
        anim.play(want)
# 方向翻转（侧视素材必需）
if absf(velocity.x) > 1.0:
    anim.flip_h = velocity.x < 0.0
```

- 若想区分 walk/run：用移速阈值（如 <70 用 walk，≥70 用 run），或近战怪直接 run（本作敌人只有接近玩家和攻击两种状态，walk 可留给慢速怪如 crystal_sentry 演示用）。
- `charge` 冲锋时可用 `speed_scale = 1.6` 让 run 动画加速（`_charge_state == 2` 时），不加新字段。

### 4.4 动画参数建议

| 动画 | 帧数 | FPS | 循环 | 周期 | 备注 |
|---|---|---|---|---|---|
| idle | 4 | 5~6 | 循环 | 0.7~0.8s/圈 | 与现怪 6FPS 观感一致 |
| run | 6 | 10~12 | 循环 | 0.5~0.6s/圈 | 四足奔跑典型速度 |
| walk | 6 | 8 | 循环 | 0.75s/圈 | 可选 |
| hit | — | — | — | — | 表无真实动画，跳过 |

## 五、通用化建议（30 种怪的动画路径）

### 5.1 现有 15 怪：已是"帧动画"，只是帧少

- 全部走 `_1/_2/_3/_4.png` 多帧 idle（Retro-Lines 16x16 网格裁剪 2x，mimic 4 帧、slime 3 帧）——机制本身已生效，玩家感受到的"平移感"来自帧数太少（2 帧 6FPS ≈ 3 次/秒闪动）。
- **零成本升级**：Retro-Lines `Enemies.png`（272x336 = 17x21 格，非空 264 格）中已用怪多数还有未用帧（如 ghost 有 6 帧可用、imp 5 帧、spider 4 帧），把 `frames` 从 2 提到 4~6 并补帧文件即可，不改代码。

### 5.2 新增 15 怪：本地素材已覆盖，动画现成

- **Pixel Crawler Free Pack 2.11**（实测）：Mobs 8 种（Orc 4 变体 + Skeleton 4 变体），每种都有 Idle（128x32 = **4 帧 @32x32**）、Run（384x64 = **6 帧 @64x64**）、Death sheet——**完整动作集，切帧即得 idle+run+死亡动画**。30 种方案中 cultist/bone_arbalest/gravedigger/temple_guardian/shadow_stalker 5 种正计划用它（换色），动画可直接带上。
- **Retro-Lines 剩余约 230 个非空图块**：16x16 统一网格，`cut_atlas.py` 已预设 GRID；挑图后 4~6 帧/怪。
- **Legacy-Fantasy 其余生物**（同包）：Snail（32x32 sheet）、Small Bee（64x64 sheet）、Character（64x64/64x80，Attack/Idle/Run）——切割脚本已有预设。
- 补充：`wolf 灰狼`计划用"Legacy-Fantasy Boar Idle f0/f3 换银灰"（《怪物图标替换报告.md》），野猪动画落地后 wolf 可**直接复用 run 表银灰换色**，一举两得。

### 5.3 落地成本递减

| 怪类别 | 动画成本 |
|---|---|
| 双帧老怪升 4~6 帧 | 仅补帧文件 + `frames` 改数，0 代码 |
| Pixel Crawler 8 种 | 切帧 + 换色脚本（已有 import_new_enemies.py 先例）+ 配置，0 代码 |
| 新怪首接多动画（野猪） | 一次 enemy.gd 小改，后续全复用 |
| 状态切换（idle/run/walk） | 一次性通用逻辑，所有怪免费获得 |

### 6.2 风险

| 风险 | 等级 | 说明/对策 |
|---|---|---|
| 帧宽认知错误（32 vs 48） | 已消除 | 自相关 + 脚本预设双验证；切帧时务必 `--pitch 48`，否则切出 9 张错位图 |
| Hit 表无动画 | 低 | 已实测 4 帧全同；受击沿用 `_flash()` 白闪，不接 Hit |
| .import 生成 | 低 | 新增 PNG 需跑一次 Godot 导入；headless 导入会写 `.godot/imported` 与 `.import` 文件，属项目内正常产物（落地时执行，本次未跑） |
| 动画切换性能 | 无 | 每怪 1 个 AnimatedSprite2D、一次只画 1 帧、场上 ≤32 怪；切换只在状态变化时 `play()` 一次 |
| flip_h 引入回归 | 低 | 只对 `velocity.x` 符号翻转；正视图怪不受影响（flip_h 对中心对称素材不可见） |
| 视觉尺寸（48x32 vs 32x32） | 低 | 用 `size: 0.7~0.85` 缩放（scale 已有字段），不缩放像素 |
| `set_animation_loop` 弃用警告 | 无 | 新代码直接用 `set_animation_loop_mode` |

---

## 七、优先级建议

- **P0（先做，收益最大）**：野猪接入——切帧 → 配置 → enemy.gd 多动画 loader（含 flip_h）→ 状态切换按速度阈值。完成后"怪物奔跑放帧动画"诉求闭环，且所有后续怪免费获得多动画能力。
- **P1（顺手做）**：wolf 复用野猪 run 表（银灰换色）；Pixel Crawler 5 种计划怪带 Idle/Run/Death 动画接入。
- **P2（低成本视觉升级）**：现有 15 怪把 `frames` 2→4~6（Retro-Lines 剩余帧）；慢速/炮台怪演示 walk。
- **暂不做**：Hit/Death 专用动画（受击白闪 + 死亡爆炸已覆盖）、Sprite2D+hframes+AnimationPlayer 改造（无收益）。
