# 怪物技能设计方案（15 种小怪 + 公共技能池 + 精英扩展）

> 日期：2026-08-11 · 范围：仅设计文档与数据表，**未修改任何游戏代码**
> 依据：`data/enemies.json`（15 怪 + 6 Boss）、`scripts/enemies/enemy.gd`（现有 behavior/精英技能）、`scripts/enemies/boss.gd`（技能类型与预告体系）、`data/balance.json`（难度曲线）

## 一、设计原则（调研结论与来源）

### 1.1 调研过程与网络限制（如实说明）

尝试了 Bing（含 ensearch 英文市场）、DuckDuckGo（html/lite）、Mojeek、Yahoo、Google、Startpage 等搜索引擎，均被验证码拦截或返回陈旧缓存结果（Bing 连续多次返回无关的 QQ 邮箱缓存页）；Wikipedia API、Reddit、Fandom wiki、wiki.gg 均不可达。仅有 RPS 站点可达但其站内搜索也忽略了查询词。**结论：本环境外网检索实际不可用**，以下设计原则基于两份可信来源：

1. 项目内既有引用表：[Boss技能扩展方案.md](Boss技能扩展方案.md) 已记录四款参考游戏与本项目机制的映射（以撒 Mom 脚踩→leap、Hush 弹幕环→spiral；吸血鬼幸存者→wall/homing_shot；雨中冒险 2 Stone Titan→sweep、Wandering Vagrant→ring/enrage；元气骑士→spike_trail/blink）。
2. 对四款游戏的机制知识（标记为「领域知识」，未能在本次会话内联网核验原文）。

### 1.2 小怪技能设计原则（含出处）

| # | 原则 | 内容 | 出处 |
|---|---|---|---|
| 1 | 层次不过载 | 小怪按职责分层：近战肉盾（推进）、远程骚扰（压制）、精英爆发（威胁锚点）；**单只小怪 1 个主动技能即可**，战场复杂度来自组合而非单怪多技能；对齐 balance.json 的 `overwhelm_dps_ratio 1.2` | 吸血鬼幸存者 · 领域知识；项目 balance.json |
| 2 | 预告公平性 | 所有可规避伤害必须有 ≥0.5s 视觉预告，**预告几何必须等于伤害几何**（红圈=落点、红线=射线、点=发射点）；本项目已实现 circle/line/dot 三色系统，Boss 方案 v2 已立此铁律，小怪技能沿用 | 以撒/元气骑士 · 领域知识；项目 Boss技能扩展方案.md |
| 3 | 技能可规避性 | 弹幕留窄缝：扇形弹幕间隔 ≥ 1.5 倍玩家直径；环形弹幕低弹量（小怪 6-8 发，Boss 16-24 发）；地面圈给 0.4-0.6s 反应时间（玩家 dash 0.18s / 520 速可穿） | 元气骑士 · 领域知识；项目 balance.json |
| 4 | 公共技能池 | 技能作为可复用组件挂到不同怪上（词缀式设计），同一技能用参数差异化（弹速/弹数/范围/CD），降低实现成本、提高辨识度 | 雨中冒险 2 / 枪火重生 · 领域知识 |
| 5 | 形象辨识 | 独特技必须一眼可认：史莱姆=分裂、幽灵=相位、蜘蛛=网、魔像=伪装；技能服务于形象而非纯数值 | 以撒 · 领域知识 |
| 6 | 精英=锚点 | 精英制造「决策点」：狂暴（时间压力）+ 召唤（数量压力）+ 独特技（空间压力），三类压力轮换、不同时叠加 | 吸血鬼幸存者 · 领域知识 |
| 7 | 数值纪律 | 技能伤害 1.0-2.5x 攻击；小怪 CD 与小怪 TTK（1.5s）匹配——一只怪在击杀窗口内最多触发 1 次技能；精英 CD 6-8s | 项目 balance.json ttk |
| 8 | 预告强度分级 | 慢速弹（160-200）用发射点小圈即可；高伤/必中类（狙击/光束/自爆）必须线/圈预告，且前摇 ≥0.8s | 以撒/元气骑士 · 领域知识 |

## 三、15 种小怪独特技能（enemies.json `skills` 字段）

### 3.1 Schema（与 Boss 技能同构）

```json
{
  "id": "技能唯一ID", "name": "中文名", "type": "复用Boss类型或新增类型",
  "cooldown": 5.0, "windup": 0.6, "telegraph": "circle|line|dot|省略",
  // 其余为类型专属参数：shots/spread/bullet_speed/radius/damage_mult/...
}
```

可选扩展字段（不影响 Boss 兼容）：`min_level`（解锁关卡门控）、`elite_mult`（精英强化倍率，默认 cd×0.8 / 伤害×1.3）。

### 3.2 新增类型与参数清单（实现均复用现有机制）

| 新增项 | 类别 | 复用点 | 说明 |
|---|---|---|---|
| `self_destruct` 自爆 | 新类型 | 现有 bomb 死亡自爆逻辑（`_die`） | 主动触发：蓄力闪烁→原地引爆，radius/damage_mult 参数化 |
| `zone_slow` 减速圈 | 新类型 | Boss 的 GroundZone（root_zone） | 伤害改为 0 + 圈内施加 slow 状态（EventBus.apply_status 已存在） |
| `stealth_ambush` 隐身偷袭 | 新类型 | 现有 vanish behavior（无敌+半透明） | 隐身 N 秒后在玩家背后现身，立刻释放扇形弹幕 |
| `invuln` 穿行无敌 | 新参数 | `_invuln_left` 已存在 | charge 类技能穿行期间无敌 |
| `counter` 盾反 | 新参数 | take_damage 的 shield 分支 | self_buff 期间近战受击反弹 1.0x |
| `around_self` 环绕喷发 | 新参数 | eruption 队列 | 喷发点围绕自身生成（环形陷阱） |
| `status` 圈状态 | 新参数 | GroundZone + apply_status | 范围圈可指定 slow/root 等状态 |
| `summon_id` 召唤对象 | 新参数 | `_cast_summon` | 召唤指定敌人（Boss 用 `_summon_enemy` 硬编码，小怪改为参数） |
| `pierce` 穿透 | 新参数 | enemy_bullet | 狙击弹穿透玩家 |

## 四、精英怪技能扩展

### 4.1 结构规则

现状：`frenzy + 1 个技能`（近战池 charge/summon/heal，远程池 triple/summon/heal）。

目标结构：**`frenzy + 2-3 个类型技能`，其中 ≥1 个为自身独特技**（精英强化参数：cd×0.8、伤害×1.3、独特技自动加入技能列表）：

```
elite.skills = [frenzy, 自身独特技, 精英池随机1-2个]
约束：不与自身已有技能类型重复（例：冲锋兽已有 charge，不再抽 elite_charge）
```

### 4.2 精英技能池

| 技能ID | 名称 | 说明 |
|---|---|---|
| elite_frenzy | 狂暴（强化） | 被动触发：5s 内移速+60%、攻击+50%、技能CD-30%（现有 3s 升级） |
| elite_charge | 精英冲锋 | 近战池：蓄力 0.5s 直线冲撞，伤害 1.5x |
| elite_triple | 精英三连 | 远程池：3 发扇形弹，间隔 12° |
| elite_heal | 精英治疗 | 回 3% 最大生命（现状保留） |
| elite_summon | 精英召唤 | 召唤 1 只弱化同类小怪（10s 自毁，现状保留） |
| elite_shield | 精英护盾 | self_buff armor 0.5 持续 3s，金色护盾环 |
| elite_ring | 精英弹环 | ring_mini 强化版：8 发环形弹幕，逼走位 |
| elite_roots | 精英根须 | root_zone 减速圈：radius 80 / 3s / slow 45% |
| elite_fan | 精英扇射 | fan_shot 强化版：5 发 / 40° 扇形 |

### 4.3 分配示例

## 五、落地步骤（本次未改代码）

1. **数据先行**：将 3.4 节的 `skills` 数组写入 `data/enemies.json` 的对应敌人（每怪 1-2 个技能，独特技 ≥1）；精英配置写入 `elite` 字段。
2. **小怪技能调度**：`enemy.gd` 增加普通怪技能调度（仿 `boss.gd` 的 `_pick_skill/_start_skill`，简化为：CD 到且距离/血线条件满足时随机施放 1 个）；现有 behavior 字段保留兼容（behavior 继续驱动移动/被动，skills 驱动主动技）。
3. **新类型实现**：按 3.2 表逐项实现（全部复用现有机制，只增不改）：self_destruct→bomb 逻辑参数化；zone_slow→GroundZone+apply_status；stealth_ambush→vanish+扇形弹；enemy_bullet.gd 增加 status/pierce 参数。
4. **预告一致性**：新技能 telegraph 必须与实际伤害区一致（circle=落点红圈、line=射线红线、dot=发射点），沿用 Boss 方案 v2 铁律。
5. **测试**：仿 `test_boss_skills.gd` 编写 `test_enemy_skills.gd`（debug_cast→telegraph 生成→cast 完成→状态恢复），用 Godot console `--headless` 运行（环境铁律：`$env:TEMP/$env:TMP/APPDATA` 指向 `.tmp`，禁止 GUI）。
6. **平衡校准**：对齐 balance.json——小怪技能 CD ≥ 4s（TTK 1.5s 内最多触发 1 次）、伤害 1.0-2.5x 攻击、精英 CD 6-8s；关卡难度曲线 `1.22^level` 只缩放属性不缩放技能机制。
7. **验收**：smoke_test 全绿；场上 ≤32 怪性能约束下技能特效分级复用（fx_hit 轻量级）；预告一致性抽查。
