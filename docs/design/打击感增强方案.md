## 一、现状盘点（代码审计结论）

| # | 现有实现 | 问题 |
|---|---|---|
| 闪白 | enemy.gd `_flash()`：AnimatedSprite2D modulate 3→1、0.12s；fx_manager `_on_fx_hit_flash()`：**根节点** modulate→(3,3,3)→恢复、各 0.04s | 双通道冲突：① `_apply_status_visual()` 每物理帧覆写 spr.modulate，毒/燃/冻激活时 sprite 闪白被覆盖；② 根节点 modulate 影响全部子节点（StatusAttach 电弧/冰壳跟着闪，见官方文档 modulate 说明）；③ 高频命中时 tween 反复重启，只看到最后一次；④ 无普通/暴击区分 |

| 震屏 | camera_shake.gd `shake(power)`：固定 0.15s、随机 offset、新 shake 杀旧 tween | 无振幅-时长分级、无冷却 → 高频命中时小振幅连抖；普通命中也会随爆炸频繁小震 |
| 音效 | SfxBus `play(path, vol, pitch)`：new AudioStreamPlayer 播完自毁 | 无对象池、无节流、无随机变调；assets/audio 已有 7 个 ogg（zap/laser1/laser2/two_tone/shield_up/shield_down/lose）可复用 |
| 性能约束 | spell_caster `MIN_CD=0.05s`（攻速/冷却聚合后可 <50ms/发）；近战 0.8/(1+as)s；性能文档热点 2/3：粒子与弹体高频 new/free | **任何 FX 增强必须带频率上限与存活上限，否则高攻速放大卡顿** |

## 二、资料结论摘要（含来源）

### 2.1 游戏手感理论要点
- 打击感（game feel / juice）三大支柱：**命中确认**（闪白/粒子/伤害数字）、**动势反馈**（击退/震屏）、**节奏变化**（顿帧/慢动作）。出处：Steve Swink《Game Feel》（2009）；Jan Willem Nijman "Juice It or Lose It"（GDC 2013，GDC Vault 需 JS 未能抓取正文，仅理论出处）。
- GDQuest《Juicing up your game attacks》（2025-10-09，已按 Godot 4 重写）给出的标准命中反馈链：受击方**闪白 + 受击旋转 + 击退 + 伤害标签**；命中瞬间**短暂冻结时间**；粒子分层。明确指出"即使小细节也对体验影响巨大"，且"原则适用于任何攻击类型"。其击退实现：`velocity` 由 `lerp(force, ZERO, delta*10)` 衰减 + `move_and_slide()`。

### 2.2 Godot 实现结论（官方文档核验）
1. **hitstop 用 Engine.time_scale 而非 get_tree().paused**
   - 官方文档：`Engine.time_scale` 是"游戏内时钟相对真实时间的倍率，影响 Timer、SceneTreeTimer 及所有基于 delta 的模拟（_process/_physics_process）"；**不影响音频播放**（音频变速用 AudioServer.playback_speed_scale）；**建议保持 > 0.0**。→ 用 0.05~0.15 因子而非 0。
   - `SceneTree.paused` 会停物理/碰撞并按 `Node.process_mode`（PAUSABLE/WHEN_PAUSED/ALWAYS）过滤回调。本项目多处 `await get_tree().create_timer()`（enemy 图腾、Boss 施法），暂停树会让这些流程冻结，改造面大；而 time_scale 一线生效、恢复机制项目已实现（_on_slow_mo），**推荐 time_scale 方案**。
2. **闪白用 CanvasItem.modulate/self_modulate**：官方文档注明 `modulate` 影响子节点、`self_modulate` 仅自身。→ 敌人闪白应在 sprite 上做，并与状态着色合并计算；避免改根节点以免 StatusAttach 连带闪烁。
3. **击退用 CharacterBody2D.velocity + move_and_slide()**（官方教程），衰减用 GDQuest 的 `lerp(knock, ZERO, delta*decay)` 模式。受击保护共存：invuln 时 take_damage 已提前 return；root/freeze 时清零击退速度；精英/Boss 免疫保留。
4. **音效变奏用 AudioStreamRandomizer**：官方文档原文——"每次从列表随机选流，并随机音高/音量偏移，适合频繁播放的声音做变奏"。本项目可纯代码构造（pitch_scale 随机）或建随机器资源。
5. **震屏**：社区模式（Godot 论坛话题 140293 "Hit reaction location"，Godot 4.6.3/4.7，讨论 shake/hit-stop/knockback 归属）——hitbox 携带 shake/knockback/slow 参数、hurtbox 触发、shake 做成独立组件/方法；shaker 应支持振幅-时长-衰减三参数。

## 三、分级方案

**总原则**：只做信息增强、不改伤害判定与数值；全局 `juice_level`（0=全关 / 1=仅 P0 / 2=默认 / 3=全开高频）；所有参数集中在 fx_manager 顶部 `GFEEL_*` 常量区 + Settings autoload 持久化；每项带开关与频率上限（对齐性能优化文档热点 2）。

### P0 ｜ 命中确认强化（收益最大、无副作用风险）

**P0-1 受击闪白统一**（enemy.gd）
- 实现：停用根节点闪白通道（fx_manager 的 `_on_fx_hit_flash` 改为：目标有 `on_hit_flash()` 方法（EnemyBase）则委托，否则维持原根闪白逻辑给玩家）；enemy 侧 `_flash(power)` 只写 `_flash_power`，由 `_apply_status_visual()` 统一计算 `spr.modulate = base_tint * flash_color`，flash 强度按指数衰减（避免与状态着色互相覆盖）。
- 参数：`FLASH_DECAY = 12.0/s`（约 0.12s 归零）；普通 `Color(2.6, 2.6, 2.6)`；暴击 `Color(3.2, 2.9, 2.1)`（金白）；治疗闪沿用现有绿调。
- 开关：`juice_flash ∈ {0, 1}`。

**P0-2 击退强化**（enemy.gd）
- 实现：新增 `_knock_vel: Vector2`；`take_damage` 改为 `_knock_vel = dir * power`（移除瞬移位移）；`_physics_process` 中 `_knock_vel = lerp(_knock_vel, ZERO, DECAY * delta)`，`velocity = ai_vel + _knock_vel` 后统一 `move_and_slide()`；root/freeze 期间清零击退；精英/Boss 免疫保留（Boss 可选微型 20px/s 震感）。
- 参数：`KNOCK_POWER = 120.0` px/s（约位移 power/decay ≈ 12px，与现 9px 相当但带惯性过程）；暴击 ×1.6；`DECAY = 10.0/s`（GDQuest 同量级）；体型补偿 `power / (1 + 0.5 * (scale.x - 1))`。
- 开关：`juice_knockback ∈ {0, 1}`。

**P0-3 命中粒子方向 + 暴击强化**（fx_manager / event_bus / projectile / melee_attack）
- 实现：`EventBus.fx_hit(pos, kind, dir := Vector2.ZERO)` 增加可选第三参（GDScript 默认值向后兼容，旧调用不受影响）；命中方传 `(enemy.pos - player.pos).normalized()`；`HIT_RECIPES` 粒子按 dir 锥形溅射一半（另一半保持径向）；暴击追加 1 个小型扩散环（复用 `_spawn_ring`，参数 `[1.6, 0.18, 1.8]`）。
- 节流：`HIT_FX_MIN_INTERVAL = 0.03s`（按 kind 全局），`HIT_FX_BURST_MAX = 24次/s`；DOT 已有 0.35s 节流不动。
- 开关：`juice_hit_particles ∈ {0, 1}`。

**P0-4 伤害数字加强**（damage_number.gd / fx_manager）
- 实现：`play()` 增加弹出 overshoot（scale 0.6 → 1.15 → 1.0，0.18s，EASE_OUT）；暴击数字 1.8x + 随机横向位移 ±10px + 轻微旋转 ±4°；普通数字上限控制。
- 节流：`DMG_NUM_MAX_ALIVE = 24`（超限时最老数字加速淡出）；`DMG_NUM_PER_FRAME = 8`（超出合并进最近数字或丢弃）；DOT 数字保持 0.8x 小字号。
- 开关：`juice_damage_number ∈ {0, 1}`。

### P1 ｜ 顿帧 hitstop（仅暴击 / Boss 命中 / 击杀，<100ms）

- 实现：
  1. fx_manager 连接 `EventBus.fx_hit_slow`（**目前 5 处发出、0 处监听**，含 wind/curse/summon 技能），`_on_fx_hit_slow(target)` 触发小顿帧（精英/Boss 用 Boss 档）；
  2. projectile.`_hit_enemy` 与 melee.`_swing` 在 `crit` 或 `target.is_boss` 时补充 emit `fx_hit_slow`（或新增专用信号 `hitstop(factor, duration)`）；
  3. 复用 `_on_slow_mo` 机制：`Engine.time_scale = HITSTOP_FACTOR`，恢复 tween 用 `TWEEN_PROCESS_IDLE + set_ignore_time_scale(true)`（项目已验证）。
- 参数：`HITSTOP_FACTOR = 0.05`（官方建议 >0.0，不要 0）；普通命中 0ms；暴击 `0.06~0.08s`；Boss 命中 `0.08s`；击杀 `0.05s`；**冷却 `HITSTOP_COOLDOWN = 0.15s`**（高攻速暴击连发不叠加、不卡手）。
- 与现有 slow_mo 共存：统一到一个 time_scale 控制器——hitstop 到来时杀旧 tween 直接置 factor，恢复目标统一 1.0；连杀慢动作（0.8x）与 M10 慢动作沿用原逻辑，hitstop 与其冲突时后者覆盖、恢复回 1.0。
- 为什么不用 paused：见 2.2-1（create_timer 冻结、UI/物理联动改造面大；time_scale 全局一致且已有恢复机制）。
- 开关：`juice_hitstop ∈ {0, 1}`；连杀慢动作开关沿用现状。

### P2 ｜ 震屏分级 + 音效

**P2-1 震屏分级**（camera_shake.gd）
- 实现：`shake(power, duration = 0.15, priority = 0)`；新 shake 仅在 priority ≥ 当前或冷却已过时生效（保留"新震覆盖旧震"语义）。
- 振幅-时长表：普通命中 **0**（防刷屏，由粒子/数字承担确认）；暴击 2.0/0.12s；Boss 命中 3.5/0.22s；Boss 死亡 12/0.5s（现有 12）；爆炸 3.0（现有）；玩家受击 2.5（现有）；死亡炸弹 6.0（现有）。
- 冷却：`SHAKE_COOLDOWN = 0.08s`，同帧多次取最大值。
- 开关：`juice_shake ∈ {0, 1, 2}`（1=仅大事件，2=默认）。

**P2-2 音效**（sfx_bus.gd / 复用 assets/audio）
- 实现：SfxBus 增加 `play_hit(kind, crit)`：`pitch_scale` 随机 ±12%（或建 AudioStreamRandomizer 资源）；16 个 AudioStreamPlayer 池轮换（替代每次 new）；节流 `HIT_SFX_MIN_INTERVAL = 0.04s`。
- 资产映射（初版，测试后定夺）：普通命中 `sfx_zap.ogg` -10dB；暴击 `sfx_laser2.ogg` -6dB、pitch +0.15；击杀 `sfx_two_tone.ogg`；玩家受击 `sfx_shield_down.ogg`；护盾 `sfx_shield_up.ogg`；Boss 命中 `sfx_laser1.ogg` 降调 -0.15。
- 开关：`juice_sfx ∈ {0, 1}`；音量可并入 Settings（当前无音量设置项，可顺带加）。

## 七、结论

- 项目已有打击感地基（闪白、小击退、命中粒子、伤害数字、慢动作、震屏、SfxBus），**缺的不是功能而是"分级 + 频率控制 + 统一调度"**：双闪白冲突、击退无惯性、命中反馈无方向、数字/粒子无上限、hitstop 信号发了没人听。
- 最高性价比顺序：**P0 全套 → P1 hitstop（接 fx_hit_slow，改动极小）→ P2 震屏分级 → P2 音效**。
- Godot 侧全部用官方支持的 modulate / velocity+move_and_slide / CPUParticles2D / Engine.time_scale / 随机音高实现，无需新资产、无需改数值。
