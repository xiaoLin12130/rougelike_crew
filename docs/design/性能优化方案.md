# 性能优化方案（调研 + 项目分析，实施排期：当前需求完成后）

> 2026-08-10 · 依据：Godot 官方性能文档（general/cpu/gpu optimization）
> 方法：官方指南 → 项目代码扫描 → 分级优化方案

## 一、官方优化方法要点（Godot docs）

1. **测量优先**：用 profiler 定位瓶颈，避免盲改（官方首要原则）
2. **节点成本**：节点越多开销越大；`_process/_physics_process` 沿树传播——大节点数时关闭不需要的 process；少节点多内容（CanvasItem 合并绘制）
3. **对象池**：高频创建/销毁的对象（弹幕/粒子/飘字）用池复用，避免 GC/分配抖动
4. **树管理**：暂停/隐藏不如移出 SceneTree；大场景分段加载
5. **物理**：保持 60Hz tick；减少物理对象与碰撞层
6. **渲染**：纹理压缩、图集、少 draw call（Web 端 for_desktop=false 已设）

## 二、项目代码扫描结论（2026-08-10）

### 热点 1：每帧全树搜索敌人（P0 优化点）
- `get_nodes_in_group("enemy")` 在 **20+ 文件**使用（synergies 12 个脚本的钩子回调、combat、enemy 自身）
- 敌人上限 32 只时每次全树搜索 O(n)；钩子每帧多次触发（enemy_status/enemy_died 等）
- **方案**：spawner/level 维护**常驻敌人数组缓存**（enemy 进入/退出树时更新），synergy 钩子改读缓存；或在 synergy 基类做一次性查询缓存（每帧最多一次）

### 热点 2：粒子高频创建/销毁（P1 优化点）
- fx_manager 7 处 `CPUParticles2D.new()`——每次爆炸/施法新建粒子节点，发射完自毁
- 高攻速+多弹时每秒创建数十个粒子节点 → 分配抖动
- **方案**：粒子对象池（复用已结束的粒子节点）；或爆炸特效合并为单节点多粒子

### 热点 3：弹幕/召唤实例化（P1 优化点）
- projectile/spell_caster/summon 每次施法 instantiate——5 连发×3 法杖高频创建
- **方案**：projectile 对象池（命中/到射程后回收复用，需要状态重置）

### 内存泄漏排查结果（已检查）
- DamageNumber 0.6s 自毁 ✓；GroundFX 全局限量 30 + 自毁 ✓（Goodall 验证）；召唤光环 freed-instance 已修（Planck）
- EventBus 连接随节点释放自动断开（Godot 自动管理）✓
- synergy 钩子全局常驻不泄漏 ✓
- **结论：无确认泄漏；主要风险是高频创建/销毁的分配压力**

## 三、分级优化方案（实施顺序）

| 优先级 | 优化项 | 预期收益 | 改动范围 |
|---|---|---|---|
| P0 | 敌人数组缓存（替代全树搜索） | 战斗帧 CPU 明显下降（synergy 多钩子场景） | spawner/enemy/synergies 基类 |
| P1 | 粒子对象池 | 特效密集场景帧率稳定 | fx_manager |
| P1 | projectile 对象池 | 高攻速多弹场景帧率稳定 | projectile/spell_caster |
| P2 | 关闭不可见节点的 process | 主菜单/暂停时零开销 | 各 UI/场景 |
| P2 | Web 纹理压缩/图集（待评估） | 加载与显存 | 导出配置 |

## 四、验收方式

- 用 `--fixed-fps` 基准：同样 60 秒战斗场景，优化前后 `Engine.get_frames_per_second()` 均值对比
- 敌人 32 上限 + 高攻速（5 连发×3 法杖）压力场景，无掉帧/卡顿
- 内存：`Performance.get_monitor(Performance.MEMORY_STATIC)` 长时间运行平稳（无持续增长）
- 回归：全部既有测试全绿
