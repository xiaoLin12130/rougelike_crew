# 商店页面修复报告（2026-08-12）

范围：`scripts/ui/game/wand_shop.gd`（商店）＋测试文件＋本文档；未触碰 hud.gd / build_panel.gd / enemies / fx / combat（另一代理并行中）。

## 一、4 项修复说明

### 1. 去掉选择页“关闭”按钮
- 删除 `_build_menu_page()` 中的 CloseBtn 按钮块（原 171-175 行）。
- 选择页按钮顺序现为：**强化 → 购买 → 构筑 → 回血 → 开始下一波（金色）**；退出商店统一由金色“开始下一波”（NextWaveBtn，原本就连 `_close_shop()`）完成，不再有第二个退出入口。
- 同步更新两处注释（按钮顺序说明、“唯一退出入口”）。

### 2. 构筑买完直接关闭商店
- `_buy_build_item()` 购买成功后在原有 `_build_bought = true` / `_roll_build_offers()` / `_refresh()` 基础上，追加 `get_tree().create_timer(0.5).timeout.connect(_finish_build_close)`。
- 新增 `_finish_build_close()`：与强化路径 `_finish_enhance_close()` 同款守卫（`_shop_open` 才关），节点释放后信号连接自动失效、防重入。
- 延迟说明：法杖购买是立即 `_close_shop()`；构筑购买采用 0.5s 展示延迟，让玩家看清购买成功后再关闭进下一关（避免即时关闭看不到反馈）。

### 3. 法杖卡图标被锁盖住＋无法点击购买
- 根因（headless 实测确认）：LockBtn 偏移 `offset_top=-30 / offset_bottom=-8`，锚点 TOP_RIGHT 下按钮实际矩形为 y=-30..-8，**整个悬在卡片上方**，渲染覆盖上一行卡片区域并拦截该处点击（点击落在锁钮上被按钮消费，整卡 `gui_input` 收不到 → 无法购买）。
- 修复：`offset_top=4 / offset_bottom=24`（保持 `offset_left=-30→-28` 语义、`offset_right=-8`），锁钮落在卡片内右上角 20x20（x=110..130, y=4..24，卡 138x150）。实测确认 Godot 4.7 PanelContainer 保留子节点锚点（未被拉伸铺满），无需改卡片结构。
- 购买链路：整卡 `gui_input` → `_buy_wand()` 保持不变；锁钮 20x20 仅占右上角，图标/名称/价格行点击均落到卡片购买；锁钮自己的 20x20 区域仍可切换锁定（设计意图）。

### 4. 强化页/强化卡文本“???”码点
- 排查结论：wand_shop.gd 内**无任何 `Label.new()` 直建文本**（全部走 `UiTheme.label()`/`UiTheme.button()`，均已设置中文字体；替换模式 `Button.new()` 也走了 `UiTheme.apply_font`；LockBtn 为纯图标无文字）。
- 真正根因（fontTools 扫描全文件字符串字面量）：唯一缺字形字符是 **U+FF5C 全角竖线 `｜`**，用于强化卡统计文本 `"Lv.%d ｜ 伤害 +%d%%（×%.2f）"`（字体子集 LXGWWenKai_subset.ttf 无此字形 → 显示码点）。
- 修复：改用子集已覆盖的间隔号 `·`：`"Lv.%d · 伤害 +%d%%（×%.2f）"`。
- 附带校验：`×`、`→`、`←`、`·`、`！`、`【】`、`「」`、`（）、：，。` 等全部在子集覆盖内；wands.json / spells.json 数据文本也无缺字。

## 四、超出本任务文件边界的遗留发现（数据层，未改动）

fontTools 扫描数据文件发现两处会在商店界面露出码点/占位的**数据问题**，均位于 `data/items.json`（不在本次允许改动文件内，建议数据侧修复）：

1. 某防御流派物品描述含 **U+2265 `≥`**（“减伤 ≥30% 后免疫击退…”），中文字体子集无此字形 → 构筑卡描述可能显示码点（该物品需持有防御流派才会进构筑池）。
2. `wand_expander`（法杖扩容饰品）的 `name`/`description` 是字面量 **"??????"** 数据损坏，若进构筑池会显示乱码。

建议后续：把 `≥` 改为 `>=`（或扩字体子集），并修复/补全 wand_expander 的名称与描述。
