## 7. 新发现问题（BUG 只记录不修）

### P0-1 召唤光环已释放实例崩溃（本轮新发现，当前树仍存在）
- **现象**：R1 于 t=310（L18、持有召唤流派件数 ≥3 后）起，`fx_manager.gd:1112 _refresh_summon_auras` 每帧报
  `Trying to assign invalid previously freed instance`，共 327 次；t=477.5 进程以退出码 -1 崩溃，一局疑似必胜局丢失。
- **根因**：`_summon_auras`（召唤物实例 id → 光环节点）在召唤物死亡时无清理钩子；第二循环
  `var aura: Node2D = _summon_auras[sid]` 把已释放实例赋给类型化变量 → 报错并中止当前函数（erase 未执行），
  残留条目导致**每帧重复报错**直至进程退出。
- **触发条件**：持有召唤流派构筑（光环 tier≥1）+ 任意召唤物死亡。召唤流/召唤蝙蝠构筑的常规战局即可触发。
- **修复方向**（供参考）：赋值前用 `_summon_auras.get(sid)` + `is_instance_valid` 判空，或召唤物死亡时同步 erase。

### P1-2 smoke_test 不拦截 UI 脚本解析失败（误报 SMOKE OK）
- R6 窗口实测：ui_theme.gd 解析失败时 172 个 UI 脚本加载报错，smoke_test 仍输出 SMOKE OK 且退出码 0。
- 建议 smoke 增加“启动日志无 Parse Error”断言或对 UI 脚本显式 compile 校验。

### P2-3 法杖商店格式化缺参数（每局必现）
- `wand_shop.gd:179 _refresh`：每次商店开启报 `String formatting error: not enough arguments`（7 局中 5 局有效局各 3-4 次）。

### P2-4 火系地面区数组越界（偶发）
- R2 实测：`fire_synergy.gd _ignite_zones:408/415`（remove_at 越界 + get index 越界）与 `_tick_zones:364` 各 1 次，非致命。

### P3-5 test_ground_fx 毒雾用例与实现漂移（并行提交引入）
- a94b85d 将毒M3 毒雾弥漫门控改为“需持有 poison_m3”，但 `test_ground_fx.gd _test_poison` 仍只持有 poison_m1 →
  GroundPoison 不再出现，用例失效（导出树 18:31 时该用例通过）。需同步用例或改回门控。

### 环境观测（非代码缺陷）
- R6 因并行 agent 于测试窗口写入 ui_theme.gd 中间态（FONT_CN 缩进语法错误）导致启动解析失败；
  已由 215b88a（18:57:52）修复。提示：多 agent 并行开发时 headless 测试可能撞上文件中间态。

## 8. 结论与建议

1. **P0 直击修复验证通过**：通关率 27%→80%（含并行增强加成，方向明确），Boss 战 DPS 全面上升，
   首关不再磨血；胜局耗时 514-613s，击杀/金币均超第 1 轮。
2. **新增视觉不崩溃**：地面/雷系视觉在导出树回归全绿，7 局实战无视觉报错。
3. **构筑补全/法杖重设计未破坏机制**：smoke/core_shell/lightning 全绿，冰/召唤/雷/水构筑在实战中正常结算。
4. **新 P0 需优先处理**：召唤光环 freed-instance 崩溃（当前树仍存在）——召唤流战局大概率触发，会吞掉通关局。
5. **建议**：① 修复 P0-1 并补“召唤物死亡清理”用例；② smoke 增加解析错误拦截；③ 对齐 test_ground_fx 毒雾用例；
   ④ 对纯导出版（不含四选一/XP 加速）单独复测一轮，校准 80% 胜率的“净 P0 修复贡献”。
