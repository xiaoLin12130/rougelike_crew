## 0. 游戏现有素材机制（对接基线）

| 项目 | 现状 | 对素材的要求 |
|---|---|---|
| 玩家 `scripts/player/player.gd` | `SPRITE_PATHS` 四方向字典（up/down/left/right），每方向 2 帧，`_build_frames()` 用 `add_frame` 构建 SpriteFrames，8 FPS 循环 | **每方向帧数任意**，直接改路径数组即可，无需改代码 |
| 玩家画布 | 32x32，内容实际 22x31px，8 色（紫袍法师 #583496/#7c4cc8 + 金饰 #ffd25a + 肤色 #f0d6aa） | 新素材目标画布 32x32 或 64x64（AnimatedSprite2D 可偏移） |
| 敌人 `scripts/enemies/enemy.gd` | `enemies.json` 的 `sprite` + `frames` 字段：`_1.png` 自动替换为 `_2.png`…`_N.png`；`frames=1` 即静态单帧 | **任意帧数、单帧亦可**；新增敌人= 放 PNG 序列 + JSON 加条目 |
| 敌人画布 | 32x32，2 帧待机；boss 单帧 + `size` 倍率（1.6~2.4） | 侧视/俯视皆可（现敌本无双方向） |

## 4. 侧视 vs 俯视判定与适配方案

### 4.1 判定结论

| 包 | 视角 | 四方向？ | 俯视角适配 |
|---|---|---|---|
| **Mana Seed** | 3/4 俯视角色（Seiken Densetsu 式） | **是（下/上/左/右 4 行）** | **零适配**，方向行直接用 |
| **Gandalf** | 纯侧视（面朝右） | 否 | 需要"侧帧复用"方案 |
| **Retro-Lines** | 16px 俯视（Zelda 式） | 部分（待机俯视+行走正面） | 零适配，2x 放大即可 |

### 4.2 侧视帧用于俯视角的通用方案（Gandalf 适用）

1. **左右朝向**：原帧 = 右，`flip_h` 镜像 = 左（0 美术工作量，像素级完美）。
2. **上下朝向**（三选一）：
   - **A. 复用侧帧（推荐，0 工作量）**：上/下直接复用镜像侧帧或原侧帧。大量俯视角 indie 游戏（包括不少商业作）采用"四向统一侧视"；本游戏敌人本就无方向帧，玩家若用侧视则全游戏观感自洽。
   - **B. 重绘上下帧（4~8h/角色）**：按侧帧逐像素画正面/背面版，需保持 18x44 骨架对齐。
   - **C. 旋转 90°（不可行）**：像素旋转会毁掉轮廓与像素网格，否决。
3. **缩放**：18x44 → 32px 目标：`0.72x`（≈13x32）或原生 1:1（44px 高，用 `size`/scale 微调）。

### 4.3 Mana Seed 的使用注意

- 帧是 64x64 画布内 14~29px 小角色，直接用会导致画面里角色偏小且锚点偏上——**必须裁剪**：按内容 bbox 裁到 ~32x64 或固定 32x32 居中，再存为单帧 PNG（PIL 脚本化，约 30 分钟工作量含调参）。
- 纸娃娃合成顺序：0bas → 1out → 4har → 5hat →（战斗页再加 6tla → 7tlb）；面向北时部分大帽子需把工具层下移（README 提示，demo 的 pnty 帽不大，基本无碍）。

### 5.3 尺寸与接入

- **原生 1:1 即可**：角色 ~29px 高 ≈ 现玩家 31px 高；64x64 帧裁剪到内容 bbox 后存 32x32 画布（居中），或直接存 64x64 并在 AnimatedSprite2D 上加 `position` 偏移。
- 若想更接近现有 22px 宽，可 1.2~1.5x 放大（最近邻，像素风无损）。
- 接入：合成裁剪后的文件命名为 `player_down_1.png`…`player_down_6.png`（与现有 `SPRITE_PATHS` 模式一致），每方向 6 帧改数组即可；8 FPS 可直接沿用，行走建议 7.4 FPS（135ms）或按 README 节奏。
- 动画节奏参考：走 135ms/帧；跑 80/55/125/80/55/125ms；斩击 160/65/65/200ms。

### 5.4 备选与排除

- Retro-Lines Player：16px、4 色、无四方向——风格差距过大，**不推荐**作玩家。
- Gandalf：纯侧视，作玩家需 4.2 节的妥协方案——**不推荐**作玩家（但适合敌人/NPC）。

## 6. 敌人补充方案（enemies.json 加条目即可）

### 6.1 立即可用（工作量 <1h）

| 新敌人 | 素材 | 帧 | 建议 JSON 参数 |
|---|---|---|---|
| 水晶哨兵 `crystal_sentry` | Retro-Lines `Enemies.png` 列 10-12（16px 菱形，2x 放大=32px） | 1-2 | hp 60 / 远程 or 冲撞 / size 1.0 |
| 蜘蛛 `spider` | Retro-Lines 底部行列 0-3（32x16，2 帧） | 2 | hp 50 / 快速近战 / size 1.2（视觉扁宽，碰撞盒调矮） |
| 魔像方块 `mimic_block` | Retro-Lines 列 5-8 中段（10x10 带脸方块） | 4 | hp 120 / 减速 / size 1.0 |

| 地精弩手换皮 | Retro-Lines 列 0-1 小地精 | 2 | 换掉/补充 `goblin_archer` 视觉 |

### 6.2 可选（工作量 1-2h）

| 新敌人 | 素材 | 说明 |
|---|---|---|

## 7. 结论清单

### ✅ 立即采用

1. **Mana Seed → 玩家替换**：唯一四方向包；0bas+pfpn/fstr+pnty 尖顶帽+dap1 即法师气质；p1 行走 6 帧×4 方向 + pONE2/3 战斗页备用；原生 1:1 尺寸与现玩家相当；管线为"PIL 合成 4 层 → 裁剪 bbox → 存 32x32 序列"，半日内可完成。
2. **Retro-Lines Enemies → 新敌人**：水晶哨兵/蜘蛛/魔像方块/幽灵至少 4 种，16px 2x 放大即 32px，enemies.json 加条目即可（含精灵裁剪共 <1h）。
3. **Retro-Lines Fireworks → 法术/爆炸特效**：12 帧火箭 + 多帧大爆炸，CC0，直接裁剪即可叠加到 projectile 命中/施法动画。

### 🟡 可选

- **Gandalf → 人类敌人/NPC**（强盗、混混；侧视在敌人侧无妥协成本，行 0 两帧待机即用）；换装层支持快速量产配色变体；许可允许商用（禁再分发/AI 训练）。
- **Mana Seed 武器层与特效**（挥砍弧光、剑/锤/盾）→ 近战或施法前摇演出。
- **Retro-Lines Bosses**（5 个 40px 大精灵）→ 中 Boss/精英。
- **Retro-Lines Environment** → 地图风格换装备选。
- **Gandalf 行 6 死亡序列** → 未来做死亡动画时的参考帧（需扩展 enemy.gd 动画状态）。

### ❌ 不适用

- **Gandalf → 玩家**：纯侧视无四方向，做玩家需 4.2 节妥协（观感突兀）或 4-8h 重绘，收益低于 Mana Seed。
- **Retro-Lines Player → 玩家**：16px、4 色、两角色共用行走帧，与现有 8 色 32px 风格差距过大。
- **Retro-Lines With-Background 变体**：背景已烘入像素，无法直接使用（只能作预览）。
- **Mana Seed 推/拉/跳动作**：游戏无推箱/跳跃机制（玩家有 dash），暂不需要。
- **Mana Seed p1 跑步帧单独使用**：跑步=行走帧+2 新帧的混合循环，需按 README 的 1,2,7,4,5,8 序列组帧，不能直接按列顺序播放。
- **Gandalf Platformer Assets / Hp bar 包**：不在本次任务范围（平台跳跃向，与本作俯视角不匹配）。
